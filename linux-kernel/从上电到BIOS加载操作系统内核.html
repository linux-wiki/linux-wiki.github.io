0. 范围与关键结论

0.1 本文默认硬件模型

本文默认讨论：

  • 架构：x86/x86-64。
  • 机器类型：普通 PC、工作站、服务器。
  • 固件：Legacy BIOS、UEFI，或带 CSM 的 UEFI。
  • 操作系统示例：Linux，但大部分流程对 Windows、BSD 等系统同样成立。
  • 启动介质：SATA/NVMe 硬盘、USB、PXE 网络启动、光盘镜像等。

不展开：

  • ARM、RISC-V、嵌入式 SoC 的 Boot ROM、SPL、TF-A、U-Boot 全链路。
  • 具体厂商私有固件实现，如 Intel FSP 内部细节、AMD AGESA 私有细节。
  • 内核接管后完整的操作系统初始化。

0.2 最重要的纠偏

严格说：

  • Legacy BIOS 通常不会直接加载操作系统内核。
  • Legacy BIOS 只加载第一个可启动扇区，通常是 MBR 或 VBR，再由 bootloader 加载内核。
  • UEFI 通常加载的是一个 EFI 可执行文件，例如 grubx64.efi、bootmgfw.efi、systemd-bootx64.efi。
  • 如果 Linux 内核启用了 EFI stub，UEFI 可以把 Linux 内核本身当成一个 EFI 程序直接加载。

2. 关键参与者

2.1 用户可见但不直接执行代码的部件

  • 电源键：通常接到主板南桥/PCH、EC 或 BMC，而不是直接切断主电源。
  • 电源供应器 PSU：把交流电转换为主板需要的直流电源轨。
  • 主板 VRM：把 PSU 的 12V 等转换成 CPU、内存、芯片组需要的低压大电流。
  • 扬声器、诊断灯、七段码：POST 错误报告手段。
  • 显示器、键盘：固件控制台输入输出设备。

2.2 会主动执行固件或管理逻辑的部件

  • CPU：最终执行 BIOS/UEFI、bootloader、内核。
  • PCH/芯片组：管理低速设备、SPI Flash、USB、SATA、PCIe root、RTC、GPIO、电源管理等。
  • EC：常见于笔记本，负责键盘矩阵、电池、风扇、盖子开关、电源键、温度等。
  • BMC：常见于服务器，负责远程管理、IPMI/Redfish、虚拟媒体、远程电源控制、SOL/KVM。
  • Intel ME / AMD PSP：平台安全与管理微控制器，可能在主 CPU 之前或并行运行平台固件。
  • GPU：有自己的 VBIOS 或 GOP driver，用于早期显示。
  • 存储控制器：SATA AHCI、NVMe、RAID HBA 等，可能有 Option ROM 或 UEFI driver。
  • NIC：PXE/iSCSI/FCoE 启动需要网卡固件参与。

2.3 固件存储位置

常见固件位于主板 SPI NOR Flash 中，里面可能包含：

  • BIOS/UEFI 主固件卷。
  • Intel ME 或 AMD PSP 固件区域。
  • GbE 网卡配置区域。
  • NVRAM 变量区。
  • OEM 资产信息、序列号、密钥、默认配置。
  • 恢复镜像或备份 BIOS 区域。

3. 断电、待机与按下电源键

3.1 G3、S5、S4、S3 的区别

状态常见含义电源情况
G3机械断电电源线拔掉或 PSU 开关关闭，待机电也没有
S5软关机操作系统关机，待机电保留
S4休眠内存内容写入磁盘，大部分电源关闭
S3睡眠内存自刷新，恢复比 S4 快
S0工作状态系统运行中

从用户视角“关机后开机”常常是 S5 → S0；“拔电再插电开机”则是 G3 → S5 → S0。

3.2 待机电源

只要 PSU 接入交流电并打开，通常会提供 +5VSB 待机电源。它用于：

  • 让电源键检测电路工作。
  • 让 EC/BMC/PCH 的待机域工作。
  • 支持 Wake-on-LAN、键盘唤醒、定时开机、远程管理开机。
  • 保存某些低功耗状态。

3.3 按下电源键时发生什么

电源键通常不是直接给 CPU 通电，而是产生一个低电平脉冲，例如 PWRBTN#：

  1. 用户按下电源键。
  2. EC/PCH/BMC 检测到 PWRBTN#。
  3. 平台根据策略判断是否允许开机：
    • 电池是否存在或电量足够。
    • 适配器功率是否足够。
    • 机箱入侵、温度、短路保护是否异常。
    • BMC 远程电源策略是否允许。
  4. 主板向 PSU 拉低 PS_ON#。
  5. PSU 开始输出主电源轨。

3.4 服务器场景

服务器可能不是本地按电源键，而是：

  • BMC 收到 IPMI Chassis Power On。
  • Redfish API 请求开机。
  • 机房 PDU 上电后根据 BIOS 策略自动开机。
  • Wake-on-LAN 唤醒。
  • RTC 定时唤醒。

这些事件最终都会进入类似的电源控制逻辑。

4. 电源与主板上电时序

4.1 PSU 输出

ATX 类 PSU 常见信号：

  • +5VSB：待机电源，先于开机存在。
  • PS_ON#：主板拉低后 PSU 打开主输出。
  • +12V：CPU/GPU/VRM 主要输入。
  • +5V：USB、部分逻辑、存储设备等。
  • +3.3V：芯片组、PCIe、低速逻辑等。
  • PWR_OK：PSU 通知主板主电源稳定。

4.2 主板电源轨转换

PSU 输出不是 CPU 可以直接使用的电压。主板 VRM 会生成：

  • CPU core 电压。
  • CPU SoC/uncore 电压。
  • 内存控制器相关电压。
  • DDR VDD/VDDQ/VPP。
  • PCH/chipset 电压。
  • PCIe、时钟、PHY、USB、SATA 等辅助电压。

这些电源轨需要按顺序上升。错误顺序可能导致芯片无法复位、锁死或损坏。

4.3 时钟与复位

CPU、PCH、PCIe、USB、SATA、内存都需要时钟。典型过程：

  1. 晶振或时钟发生器开始工作。
  2. PLL 锁定。
  3. 主板确认关键电源轨稳定。
  4. PWR_OK 或平台等价信号有效。
  5. PCH/芯片组逐步释放各模块 reset。
  6. CPU reset 被释放。

4.4 复位信号的作用

复位不是“清空所有东西”这么简单，它确保：

  • CPU 寄存器进入架构规定的复位状态。
  • 芯片组寄存器进入默认状态。
  • 总线设备处于可枚举状态。
  • 缓存、MMU、分页等高级机制处于关闭或默认状态。
  • 设备不会在电源未稳定时乱发总线事务。

4.5 上电阶段可能失败的位置

如果机器完全无反应，问题通常还没到 BIOS：

  • PSU 无待机电。
  • 电源键或前面板线缆故障。
  • 主板短路保护。
  • VRM 故障。
  • EC/BMC 固件卡死。
  • PCH 无法释放电源序列。
  • CPU 供电异常。

5. 芯片组、EC、BMC 与管理引擎的早期活动

5.1 EC

笔记本 EC 常常比主 CPU 更早工作，职责包括：

  • 检测电源键。
  • 检测 AC adapter 和电池。
  • 控制充电。
  • 控制风扇。
  • 读取温度传感器。
  • 管理键盘矩阵和触控板低级事件。
  • 控制背光、电源 LED、状态灯。
  • 参与睡眠/唤醒。

如果 EC 异常，可能出现“按电源键无反应”“风扇转但不亮屏”“无法充电”等问题。

5.2 BMC

服务器 BMC 可以在主机 CPU 关闭时运行。它可能在主机启动前完成：

  • 自身 Linux/RTOS 启动。
  • 管理网口初始化。
  • 传感器扫描。
  • 风扇策略加载。
  • 远程 KVM 准备。
  • 虚拟光驱/虚拟 U 盘挂载。
  • 记录 SEL 日志。
  • 触发主机开机。

BMC 与主机 BIOS 的关系：

  • BMC 可以向 BIOS 提供配置或传感器数据。
  • BIOS 可以通过 IPMI/KCS/BT/SSIF 与 BMC 通信。
  • BIOS POST 错误可能写入 BMC SEL。
  • BMC 可以重定向串口输出为 SOL。

5.3 Intel ME / AMD PSP

现代 x86 平台通常有独立管理/安全处理器：

  • Intel 平台常见 Intel Management Engine。
  • AMD 平台常见 Platform Security Processor。

它们可能负责：

  • 平台根信任。
  • 固件验证。
  • 安全启动前置检查。
  • 电源管理协作。
  • 某些设备或总线初始化协作。
  • 远程管理能力。
  • 密钥、TPM、fTPM 相关能力。

这些部件的固件异常可能导致主 CPU 无法开始执行 BIOS/UEFI。

6. CPU 脱离复位并执行第一条指令

6.1 BSP 与 AP

多核 CPU 启动时通常区分：

  • BSP：Bootstrap Processor，启动处理器，最先执行固件主路径。
  • AP：Application Processor，其他处理器/核心，早期一般处于等待状态，后续由固件或内核唤醒。

固件通常先在 BSP 上执行，完成基础初始化后再发现、初始化或测试 AP。

6.2 x86 复位后的典型状态

x86 CPU 复位后处于非常受限的状态：

  • 处于 real mode 类似状态。
  • 分页关闭。
  • 中断通常关闭。
  • 缓存状态受平台和固件控制，早期不可假定 DRAM 可用。
  • 寄存器处于架构规定的 reset 值。
  • CPU 从固定 reset vector 取指。

CPU 只会取地址，不知道“Flash 芯片”在哪里。映射关系由芯片组/PCH 提供：

  • SPI NOR Flash 接在 PCH 的 SPI 控制器上。
  • 平台在复位默认配置中把 Flash 的末端映射到 CPU 高地址。
  • CPU 从 reset vector 读取时，PCH 把这个访问转换为 SPI Flash 读。
  • 初始代码执行后，固件会建立更完整的内存映射和缓存策略。

6.5 第一条指令之前已经发生了什么

当 CPU 执行第一条指令时，已经完成：

  • 待机电存在。
  • 主电源轨已打开。
  • CPU 供电稳定。
  • 基准时钟稳定。
  • PCH/芯片组复位流程达到可让 CPU 取指的状态。
  • 固件 Flash 被映射到 reset vector。
  • 平台安全/管理部件可能已经运行并完成若干检查。

7. 固件最早期执行环境

7.1 早期最大限制：没有 DRAM

CPU 刚开始执行固件时，系统内存通常还不能用：

  • 内存控制器尚未初始化。
  • DIMM 参数未知。
  • DDR 训练未完成。
  • 内存时序、频率、电压、拓扑尚未确认。

因此固件早期不能像普通程序一样随便使用栈和堆。

7.2 固件早期可用的存储

早期可用的“临时存储”可能包括：

  • CPU 寄存器。
  • 少量 SRAM。
  • CPU cache 作为 RAM 使用，即 Cache-as-RAM。
  • PCH 或 SoC 内部 SRAM。
  • 固件 Flash 只读执行区。

7.3 Cache-as-RAM

Cache-as-RAM 的核心思想：

  1. 配置 CPU 缓存为不回写到 DRAM 的临时 RAM。
  2. 把一小段地址空间当作栈和临时数据区。
  3. 在 DRAM 可用之前运行 C 代码或更复杂的初始化逻辑。
  4. DRAM 初始化完成后，把临时数据迁移到真正内存。

这一步对现代固件很关键，因为纯汇编完成全部内存初始化非常困难。

7.4 固件代码解压与固件卷

BIOS/UEFI 固件为了节省 Flash 空间，通常把模块压缩存储：

  • 最早期代码不压缩或轻度压缩，必须能直接执行。
  • 早期代码解压更多模块到临时内存或 DRAM。
  • UEFI 固件常以 Firmware Volume 的形式组织 PEI/DXE 驱动。
  • 各模块带 GUID、依赖关系、压缩算法、校验信息。

7.5 固件自身的执行模式切换

固件可能逐步切换 CPU 模式：

  • 从 reset 后的 real mode 类似状态开始。
  • 进入 32 位 protected mode，以访问更大地址空间和更方便地运行 C 代码。
  • 在 UEFI x86-64 平台上，DXE 阶段通常运行在 64 位 long mode。
  • 在 Legacy BIOS 路径下，最终还需要给 MBR 提供 16 位 BIOS interrupt 服务。

8. CPU、缓存、微码与低级平台初始化

8.1 微码更新

CPU 内部有微码。固件可能加载厂商提供的微码补丁：

  • 修复 CPU 已知 errata。
  • 改变特定指令或内部状态机行为。
  • 为安全漏洞缓解提供支持。
  • 确保后续内存初始化和多核初始化稳定。

微码通常来自 BIOS/UEFI 固件镜像，也可能后续由操作系统再次更新。

8.2 CPU 基本特性探测

固件会使用 CPUID 等机制识别：

  • CPU 厂商、型号、stepping。
  • 支持的指令集和扩展。
  • 核心数、线程数、拓扑。
  • 缓存层级。
  • APIC/x2APIC 能力。
  • 虚拟化、安全、加密扩展。

8.3 MTRR、PAT 与缓存策略

固件需要配置不同地址区域的缓存属性：

  • 固件 Flash：通常不可缓存或写保护缓存。
  • MMIO 区域：不可缓存。
  • DRAM：可写回缓存。
  • 显存 framebuffer：可能写合并。

相关机制包括：

  • MTRR：Memory Type Range Registers。
  • PAT：Page Attribute Table。
  • 固件页表属性。

错误缓存属性可能导致设备 MMIO 访问异常或性能严重下降。

8.4 APIC 与中断控制器

固件会初始化或探测：

  • Local APIC。
  • IO APIC。
  • 传统 PIC 兼容逻辑。
  • 中断路由。
  • MSI/MSI-X 能力。

Legacy BIOS 需要保持传统中断模型可用；现代 OS 会在内核启动后重新配置中断系统。

8.5 多核初始化

固件可能会：

  1. 发现所有 CPU package/core/thread。
  2. 唤醒 AP。
  3. 对 AP 执行微码更新。
  4. 测试 AP 是否响应。
  5. 收集拓扑信息。
  6. 把 AP 放回等待状态。
  7. 在 ACPI MADT 等表中描述 CPU 拓扑。

操作系统后续会根据这些表重新启动 AP。

8.6 芯片组与 SoC 初始化

固件还会设置：

  • PCH 基址。
  • SPI 控制器权限。
  • LPC/eSPI。
  • SMBus/I2C。
  • GPIO。
  • 电源管理寄存器。
  • RTC/CMOS。
  • HPET 或其他计时器。
  • PCIe root complex。
  • USB/SATA/NVMe 控制器基础状态。

9. 内存控制器初始化与 DRAM 训练

9.1 为什么内存初始化复杂

现代 DDR 内存不是“插上就能访问”。固件必须处理：

  • DIMM 数量和位置。
  • 单条/双条/四条拓扑。
  • rank、bank、row、column。
  • 频率、时序、电压。
  • 信号完整性。
  • 通道间同步。
  • ECC。
  • XMP/EXPO/JEDEC 配置。
  • 服务器上的 RDIMM/LRDIMM/3DS DIMM 特性。

9.2 SPD 读取

每条内存条上通常有 SPD EEPROM。固件通过 SMBus/I2C 读取：

  • 厂商信息。
  • 容量。
  • 支持频率。
  • JEDEC 标准时序。
  • XMP/EXPO 扩展配置。
  • rank/chip 组织。
  • 电压需求。
  • 校验信息。

如果 SPD 读取失败，常见现象是不开机、报内存错误、回退低频率。

9.3 内存训练

DRAM training 目的是让内存控制器找到可靠的读写参数。可能包括：

  • Write leveling。
  • Read leveling。
  • DQS gate training。
  • Command/address training。
  • Vref training。
  • Round-trip latency training。
  • Data eye training。
  • 通道/Rank 间 skew 调整。
  • ODT 参数选择。

训练本质是在不同延迟、电压、采样点下试读写测试模式，寻找稳定窗口。

9.4 内存频率选择

固件会综合：

  • CPU 内存控制器能力。
  • 主板走线拓扑。
  • DIMM 数量。
  • SPD/XMP/EXPO。
  • 用户 BIOS 设置。
  • 稳定性策略。
  • ECC 要求。

最终选择频率与时序。失败时可能：

  • 自动降频。
  • 重试训练。
  • 恢复默认设置。
  • 清除超频配置。
  • 报内存错误。

9.5 ECC 与内存清零

服务器或工作站启用 ECC 时，固件可能需要：

  • 初始化 ECC syndrome。
  • 扫描或清零内存，避免第一次读取触发伪错误。
  • 标记坏页或隔离故障 DIMM。
  • 把 ECC 能力写入 SMBIOS/ACPI。

这也是服务器开机慢的原因之一。

9.6 DRAM 可用后的迁移

一旦 DRAM 可用：

  1. 固件建立正式栈。
  2. 从 Cache-as-RAM 迁移临时数据。
  3. 解压更多固件模块到 RAM。
  4. 建立堆分配器。
  5. 进入更高级固件阶段。

10. POST：硬件自检与错误报告

POST 是 Power-On Self-Test，即上电自检。它不是单一动作，而是贯穿固件初始化中后期的一组检查。

10.1 POST 检查对象

常见检查包括：

  • CPU 是否可执行基本指令。
  • CPU 微码是否加载成功。
  • DRAM 是否存在、容量是否合理、训练是否成功。
  • 固件校验是否通过。
  • CMOS/NVRAM 配置是否有效。
  • 显示设备是否可用。
  • 键盘控制器或 USB 键盘是否可用。
  • 存储控制器是否响应。
  • 风扇、温度、电压是否正常。
  • TPM 是否可访问。
  • 安全启动策略是否满足。

10.2 POST 报错方式

不同平台可能使用：

  • 蜂鸣器 beep code。
  • 主板 Q-Code/Debug LED。
  • 电源 LED 闪烁。
  • 屏幕错误文本。
  • 串口输出。
  • BMC SEL 日志。
  • IPMI/Redfish 事件。

10.3 为什么有时“亮屏很晚”

早期 POST 阶段可能还没有初始化显示设备。屏幕亮起前，固件可能已经完成：

  • CPU 早期初始化。
  • 内存训练。
  • 固件解压。
  • PCIe root 初始化。
  • GPU Option ROM 或 GOP 加载。

所以“黑屏几十秒”不一定代表 CPU 没有执行代码，尤其在服务器、大内存或内存训练失败重试时很常见。

11. 总线、设备与 Option ROM 初始化

11.1 PCI/PCIe 枚举

固件会遍历 PCI/PCIe 总线：

  1. 从 root bus 开始扫描 device/function。
  2. 读取 Vendor ID 和 Device ID。
  3. 判断设备类型和 BAR 需求。
  4. 分配 MMIO、I/O port、prefetchable memory 窗口。
  5. 配置 bus number。
  6. 配置 bridge、switch、endpoint。
  7. 记录设备拓扑。

11.2 BAR 分配

PCIe 设备通过 BAR 暴露寄存器或显存窗口。固件要：

  • 探测每个 BAR 需要多大地址空间。
  • 选择放到 32 位地址以下还是 64 位地址空间。
  • 避免与 DRAM、固件、APIC、HPET 等区域冲突。
  • 为 GPU、NVMe、NIC、HBA 等设备分配 MMIO。

如果启用 Above 4G Decoding，固件可以把大 MMIO 窗口放到 4GB 以上。

11.3 Option ROM

Option ROM 是设备自带的启动期固件扩展。常见于：

  • 显卡 VBIOS。
  • 网卡 PXE ROM。
  • RAID/HBA 控制器 BIOS。
  • 存储控制器启动 ROM。

Legacy BIOS 下 Option ROM 通常提供 16 位实模式代码，并挂接 BIOS 中断服务。UEFI 下设备通常提供 UEFI driver 或 GOP。

11.4 显示初始化

显示早期初始化有两条典型路线：

  • Legacy：执行显卡 VBIOS，提供 VGA 兼容文本/图形服务，例如 INT 10h。
  • UEFI：加载 GOP，提供 Graphics Output Protocol。

OS 内核启动后通常会加载自己的显卡驱动，固件显示服务只用于早期控制台和 boot splash。

11.5 USB 初始化

固件可能初始化 USB 控制器以支持：

  • USB 键盘进入 BIOS setup。
  • USB U 盘启动。
  • USB 光驱启动。
  • Legacy USB emulation，让旧系统通过 BIOS 中断访问 USB。

UEFI 下 USB mass storage 通过 Block I/O Protocol 暴露给启动管理器。

11.6 存储控制器初始化

固件需要识别可启动存储设备：

  • SATA AHCI 设备。
  • NVMe 控制器和 namespace。
  • USB mass storage。
  • RAID 虚拟磁盘。
  • SD/eMMC/UFS。
  • iSCSI/FCoE 网络磁盘。

Legacy BIOS 通过 INT 13h 或扩展磁盘服务暴露块设备；UEFI 通过 Block I/O、Disk I/O、Simple File System 等协议暴露。

11.7 网络启动初始化

PXE 启动需要：

  • 初始化 NIC。
  • 获取链路。
  • DHCP 获取 IP 和启动参数。
  • 下载 NBP，即 Network Bootstrap Program。
  • Legacy 下通过 PXE Option ROM。
  • UEFI 下通过 UEFI PXE driver 和 SNP/MNP/UDP/TCP 协议栈。

  • 中断控制器。
  • 电源管理。
  • 睡眠状态。
  • 热管理。
  • 电池和适配器。
  • 设备枚举。

SMBIOS 提供资产和硬件信息：

  • 主板型号。
  • 机器序列号。

12.3 内存图

固件必须告诉 OS 哪些物理地址可用，哪些不能用。典型类型：

  • 可用 RAM。
  • 保留区域。
  • ACPI reclaimable。
  • ACPI NVS。
  • MMIO。
  • 固件 runtime code/data。
  • 坏内存。
  • bootloader 占用区域。
  • initramfs 占用区域。

Legacy BIOS 通过 INT 15h E820 提供内存图。UEFI 通过 GetMemoryMap() 提供 UEFI memory map。

12.4 为什么内存图重要

内核不能简单地认为 0..最大内存 都可用，因为其中穿插着：

  • VGA hole。
  • BIOS ROM。
  • PCI/PCIe MMIO。
  • APIC。
  • HPET。
  • ACPI 表。
  • 固件 runtime services 区域。
  • DMA 保留区域。
  • crash kernel 预留区域。

如果内核误用这些区域，会导致启动崩溃或设备异常。

14. Legacy BIOS 启动路径

Legacy BIOS 是传统 PC 兼容启动方式。现代 UEFI 若启用 CSM，也会模拟 Legacy BIOS。

14.1 Legacy BIOS 提供的运行环境

在交给 MBR 前，BIOS 通常提供：

  • 16 位 real mode。
  • BIOS interrupt services。
  • 基本显示服务 INT 10h。
  • 磁盘服务 INT 13h。
  • 键盘服务 INT 16h。
  • 内存查询 INT 15h。
  • 低端内存数据结构。
  • 中断向量表 IVT。
  • BIOS Data Area。

14.2 关键内存区域

Legacy 启动时常见低端内存布局：

地址范围用途
0x00000 - 0x003FFInterrupt Vector Table
0x00400 - 0x004FFBIOS Data Area
0x00500 - 0x07BFF可用低端内存，常被 bootloader 使用

14.3 INT 19h Bootstrap Loader

BIOS POST 完成后通常调用 bootstrap 逻辑，传统上与 INT 19h 相关：

  1. 根据 BIOS boot order 选择设备。
  2. 使用 BIOS 磁盘服务读取第一个扇区。
  3. 检查扇区末尾签名 0x55AA。
  4. 把扇区加载到 0x0000:0x7C00 附近。
  5. 跳转执行该扇区代码。

这个扇区通常是 MBR。

14.4 MBR 结构

MBR 是磁盘第一个 512 字节扇区，结构通常为：

偏移大小内容
0x000446 字节启动代码
0x1BE64 字节4 个主分区表项
0x1FE2 字节签名 55 AA

MBR 代码空间极小，通常只能：

  • 查找活动分区。
  • 加载该分区 VBR。
  • 或加载 bootloader 的下一阶段。

14.5 VBR/PBR

VBR，即 Volume Boot Record，也叫 Partition Boot Record：

  • 位于分区起始扇区。
  • 文件系统相关。
  • 可能知道如何加载更大的 bootloader 文件。
  • Windows 传统启动链里常见 MBR → VBR → bootmgr。
  • GRUB 可能使用 MBR 后的 embedding area 加载 core image。

  • 是否有 BIOS Boot Partition。
  • /boot 文件系统类型。

  • 是否 LVM/RAID。

14.7 Legacy BIOS 访问磁盘

早期 CHS 寻址受限，后来扩展为 LBA。BIOS INT 13h Extensions 允许：

  • 使用 LBA。
  • 访问大磁盘。
  • 读取多个扇区。

bootloader 一开始依赖 BIOS 磁盘服务，等自己加载更多驱动后可以直接访问磁盘。

14.8 Legacy BIOS 的限制

Legacy BIOS 主要限制：

  • 16 位实模式入口。
  • MBR 分区表限制。
  • 传统 MBR 只能描述 4 个主分区。
  • 早期 BIOS 磁盘寻址限制。
  • 固件接口不适合现代设备模型。
  • 安全启动支持弱。
  • 启动代码受 512 字节 MBR 强约束。

15. UEFI 启动路径

UEFI 是现代 PC 固件接口。它不是“BIOS 的皮肤”，而是完整的固件架构和 OS 启动接口。

15.1 UEFI 固件阶段

典型 UEFI/PI 架构阶段：

阶段名称主要任务
SECSecurityreset 后最早期执行、建立临时环境、根信任起点
PEIPre-EFI Initialization初始化 CPU、芯片组、内存，产生 HOB
DXEDriver Execution Environment加载 DXE 驱动，初始化设备，提供 UEFI services
BDSBoot Device Selection执行启动策略，选择启动项
TSLTransient System Loadbootloader 运行阶段

ALAfter LifeOS 结束或关机后的固件阶段

15.2 SEC

SEC 阶段通常负责：

  • 从 reset vector 进入。
  • 建立最小执行环境。
  • 验证或度量后续固件阶段。
  • 设置临时栈。
  • 进入 PEI。

如果平台启用硬件根信任，SEC 之前或 SEC 中可能发生固件签名验证。

15.3 PEI

PEI 阶段负责让平台“活起来”：

  • 初始化 CPU 基本功能。
  • 加载微码。
  • 初始化 PCH/SoC 早期寄存器。
  • 初始化内存控制器。
  • 执行 DRAM training。
  • 建立 HOB，即 Hand-Off Block，记录早期初始化结果。
  • 把控制权交给 DXE IPL。

PEI 的最大里程碑是 DRAM 可用。

15.4 DXE

DXE 阶段类似一个小型驱动环境：

  • 加载 DXE Core。
  • 管理 UEFI boot services。
  • 加载平台驱动。
  • 枚举 PCI/PCIe。
  • 加载设备驱动。
  • 提供协议接口。
  • 初始化文件系统、块设备、网络栈、图形输出。
  • 构造 ACPI/SMBIOS。

UEFI 中的很多功能通过 Protocol 暴露，而不是通过 BIOS 中断。

15.5 UEFI Protocol

常见协议包括：

  • Loaded Image Protocol。
  • Device Path Protocol。
  • Block I/O Protocol。
  • Disk I/O Protocol。
  • Simple File System Protocol。
  • Graphics Output Protocol。
  • Simple Text Input/Output Protocol。
  • Simple Network Protocol。
  • PXE Base Code Protocol。
  • RNG Protocol。
  • Firmware Volume Protocol。

bootloader 可以调用这些协议读取文件、显示菜单、访问网络、获取内存图。

15.6 BDS

BDS 阶段负责启动选择：

  1. 读取 NVRAM 变量。
  2. 处理启动热键。
  3. 检查 BootNext。
  4. 按 BootOrder 尝试 Boot####。
  5. 查找设备路径。
  6. 加载 EFI image。
  7. 执行 Secure Boot 验证。
  8. 调用 StartImage()。
  9. 如果失败，尝试下一个启动项或进入 setup/shell。

15.7 ESP

UEFI 标准启动分区是 EFI System Partition：

  • 通常是 GPT 分区。
  • 分区类型为 ESP。
  • 文件系统通常是 FAT32。
  • 存放 .efi 可执行文件。

常见路径：

BOOTX64.EFI 是 x86-64 UEFI 的可移动介质 fallback 路径。

15.8 EFI image

UEFI 加载的程序是 PE/COFF 格式。固件会：

  1. 打开设备路径指向的文件。
  2. 读取 PE/COFF headers。
  3. 分配内存。
  4. 加载各 section。
  5. 处理 relocation。
  6. 验证签名或 hash。
  7. 调用 EFI image entry point。

15.9 UEFI bootloader 做什么

UEFI bootloader 常见任务：

  • 读取配置。
  • 显示启动菜单。
  • 解密或解锁 /boot。
  • 读取内核文件。
  • 读取 initramfs。
  • 构造内核命令行。
  • 选择 ACPI/设备信息传递方式。
  • 获取 UEFI memory map。
  • 调用 ExitBootServices()。
  • 跳转内核入口。

15.10 ExitBootServices

ExitBootServices() 是 UEFI 到 OS 的重要分界线：

  • 调用前，bootloader 可以使用 UEFI boot services。
  • 调用后，固件不再提供启动期服务。
  • OS 接管内存管理、中断、设备驱动。
  • 只有少量 runtime services 可继续使用，如时间、变量、重启等。

调用 ExitBootServices() 前必须获取最新 memory map，并使用匹配的 map key。若期间内存 map 变化，调用会失败，bootloader 需要重新获取。

15.11 UEFI Runtime Services

OS 启动后仍可调用的 UEFI runtime services 包括：

  • GetTime/SetTime。
  • GetVariable/SetVariable。
  • ResetSystem。
  • Capsule update。
  • QueryVariableInfo。

Linux 会把 runtime 区域纳入内存图保护，并在适当时机调用这些服务。

16. 从启动加载器到 Linux 内核

这一节以 Linux 为例。其他 OS 的细节不同，但基本目标一致：把内核映像、启动参数和必要辅助文件放到内存，然后跳转入口。

16.1 Linux 内核镜像类型

常见文件：

  • vmlinuz-*：压缩后的 Linux 内核镜像。
  • bzImage：x86 常见压缩内核格式，不表示 bzip2。
  • initrd / initramfs：早期用户空间，用于加载驱动、解密磁盘、挂载根文件系统。
  • System.map：符号表，启动不必需。
  • config-*：构建配置，启动不必需。

16.2 bootloader 加载的内容

bootloader 通常加载：

  • kernel image。
  • initramfs image。
  • kernel command line。
  • boot params/setup data。
  • ACPI RSDP 指针或 UEFI system table 指针。
  • 内存图。
  • framebuffer 信息。
  • 随机种子。
  • microcode initrd，某些发行版会把 CPU 微码作为早期 initrd 传入。

16.3 Linux x86 boot protocol

Linux x86 定义了 boot protocol。bootloader 需要：

  • 读取内核 setup header。
  • 确认协议版本。
  • 确定内核可加载地址。
  • 填写 boot_params。
  • 设置命令行地址。
  • 设置 initramfs 地址和大小。
  • 提供 E820 或 UEFI memory map。
  • 设置视频模式或 framebuffer 信息。
  • 跳转到内核指定入口。

16.4 Legacy BIOS 下 Linux 启动交接

概念过程：

16.5 UEFI 下 Linux 启动交接

常见路径一：UEFI → GRUB → Linux EFI stub。

常见路径二：UEFI → systemd-boot → Linux EFI stub。

常见路径三：UEFI 直接加载 Linux EFI stub。

这时“UEFI 直接加载内核”才比较接近日常说的“BIOS 加载内核”。

16.6 压缩内核与解压

Linux vmlinuz 不是最终运行的未压缩内核：

  1. bootloader 把压缩内核加载到内存。
  2. 跳转到内核自带的解压器入口。
  3. 解压器检查 CPU 能力和内存布局。
  4. 解压出真正的内核映像。
  5. 处理 KASLR 随机化位置。
  6. 跳转到未压缩内核入口。

严格地说，bootloader 加载的是“压缩内核镜像”，真正内核还要自解压。

16.7 initramfs 的作用

initramfs 不是内核，但通常与内核一起加载。它用于：

  • 提供早期用户空间。
  • 加载根文件系统所需驱动。
  • 处理 LVM、RAID、加密盘。
  • 执行 fsck 或挂载逻辑。
  • 切换到真正根文件系统。

如果 initramfs 丢失或不匹配，内核可能启动到一半找不到根文件系统。

16.9 交接时 CPU 状态

具体要求取决于启动协议和路径。总体上 bootloader/EFI stub 要确保：

  • 内核镜像位于协议允许的物理地址。
  • boot_params 可访问。
  • initramfs 地址和大小有效。
  • 内存图准确。
  • 不覆盖固件保留区域。
  • 在 UEFI 下已正确退出 boot services。
  • CPU 模式满足内核入口要求。

Linux 内核入口后会重新设置 GDT/IDT、页表、中断、调度器等，不依赖固件继续管理硬件。

17. 安全启动、可信启动与度量启动

17.1 Secure Boot

UEFI Secure Boot 目标是只执行被信任的 EFI image。核心变量：

  • PK：Platform Key。
  • KEK：Key Exchange Key。
  • db：允许的签名或 hash。
  • dbx：禁止的签名或 hash。

启动时：

  1. 固件加载 EFI image。
  2. 校验签名或 hash。
  3. 如果被 db 信任且未被 dbx 禁止，则允许执行。
  4. 否则拒绝启动。

17.2 shim 与 MOK

很多 Linux 发行版使用 shim：

MOK 是 Machine Owner Key，用于让用户信任自己签名的内核模块或启动组件。

17.3 Measured Boot

Measured Boot 不一定阻止启动，而是把启动过程度量写入 TPM PCR：

  • 固件度量自身和配置。
  • 度量 Option ROM。
  • 度量 bootloader。
  • 度量内核和 initramfs。
  • 后续远程证明或磁盘解密策略可基于 PCR 值。

17.4 TPM 与磁盘解密

TPM 可用于：

  • 保存密钥。
  • 绑定密钥释放条件到 PCR 状态。
  • 支持 BitLocker、systemd-cryptenroll、clevis 等方案。

如果 BIOS 设置、Secure Boot 状态、bootloader 或内核改变，PCR 变化可能导致自动解锁失败。

17.5 Intel Boot Guard / AMD 类似机制

部分平台在 CPU 执行 BIOS 主体前验证固件：

  • 验证初始启动块。
  • 防止未授权 BIOS 镜像启动。
  • 失败时平台可能直接停机或进入恢复。

这类机制发生在普通用户看到 BIOS 画面之前。

18. 常见启动介质细节

18.1 SATA/AHCI

固件需要：

  • 初始化 SATA 控制器。
  • 检测端口。
  • 识别设备。
  • 读取分区表或 ESP。
  • Legacy 下提供 INT 13h。
  • UEFI 下提供 Block I/O。

18.2 NVMe

  • 枚举 PCIe NVMe 控制器。
  • 映射 BAR。
  • 初始化 admin queue。

  • 枚举 namespace。

18.3 USB 启动

USB 启动涉及：

  • xHCI 控制器初始化。
  • 端口复位。
  • 设备枚举。
  • Mass Storage 协议。
  • SCSI transparent command set。
  • 读取 MBR/GPT/ESP。

Legacy 下还可能模拟成 USB-HDD、USB-FDD、USB-ZIP 等历史模式。

iPXE 可以支持更丰富协议：

  • HTTP/HTTPS。

19. 虚拟机里的“上电到内核加载”

虚拟机没有真实 PSU 上电过程，但有模拟等价阶段。

19.1 QEMU/KVM

典型固件：

  • SeaBIOS：Legacy BIOS。
  • OVMF：UEFI，基于 EDK II。

虚拟机启动时：

  1. hypervisor 创建虚拟 CPU、内存和设备。
  2. 把固件镜像映射到客户机物理地址。
  3. 设置 vCPU reset state。
  4. vCPU 从 reset vector 执行。
  5. SeaBIOS/OVMF 枚举虚拟 PCI 设备。
  6. 从虚拟磁盘、virtio、网络等启动。

19.2 与物理机不同点

虚拟机中：

  • 没有真实 DRAM training。
  • 没有真实 VRM 上电时序。
  • PCIe 设备多为虚拟或直通。
  • 固件启动更快。
  • ACPI/SMBIOS 由 hypervisor 生成或协助生成。
  • Secure Boot 取决于虚拟 UEFI 配置。

19.3 但抽象仍然相同

对客户机 OS 来说，仍然看到：

  • 固件。
  • 内存图。
  • ACPI 表。
  • PCI 设备。
  • 启动磁盘。
  • bootloader。
  • kernel handoff。

20. 常见故障点与定位线索

20.1 按电源无反应

可能在：

  • AC 输入。
  • PSU。
  • 5VSB。
  • 电源键。
  • 前面板线。
  • EC/BMC。
  • 主板短路。

还没到 BIOS。

20.2 风扇转但无显示

可能在：

  • CPU 供电。
  • 内存训练。
  • 固件早期崩溃。
  • GPU 初始化。
  • 显示输出选择。
  • BIOS 设置错误。
  • 外设 Option ROM 卡住。

可看 debug code、蜂鸣器、BMC SEL、串口日志。

20.3 反复重启

可能在：

  • 内存训练失败并重试。
  • 超频参数不稳定。
  • PSU 保护。
  • VRM 过流。
  • CPU 温度保护。
  • 固件恢复机制。

20.4 能进 BIOS 但找不到硬盘

可能在：

  • 存储设备供电或连接。
  • SATA 模式 AHCI/RAID。
  • NVMe 未被固件支持。
  • PCIe bifurcation 设置。
  • VMD/RST 开启导致 OS/bootloader 不识别。
  • 磁盘无有效分区表或 ESP。
  • UEFI/Legacy 模式不匹配。

20.5 找到硬盘但不能启动

可能在：

  • BootOrder 错误。
  • 缺少 ESP。
  • EFI 文件路径错误。
  • NVRAM 启动项丢失。
  • Secure Boot 拒绝。
  • MBR 签名缺失。
  • bootloader 损坏。
  • /boot 文件系统损坏。
  • initramfs 缺失。

20.6 进入 bootloader 后内核启动失败

通常已经过了 BIOS/UEFI 主阶段，问题可能在：

  • 内核文件损坏。
  • initramfs 不匹配。
  • 根文件系统参数错误。
  • 存储驱动缺失。
  • 加密盘解锁失败。
  • 内核命令行错误。
  • ACPI/固件 bug。
