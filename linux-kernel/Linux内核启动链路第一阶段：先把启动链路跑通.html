0. 本阶段要达成什么

0.1 能力目标

完成本阶段后，应该能做到：

  • 说清楚 BIOS/UEFI、bootloader、Linux kernel、initramfs、rootfs、init 的分工。
  • 知道 UEFI 启动项、ESP、GRUB/systemd-boot、vmlinuz、initramfs、kernel cmdline 之间的关系。
  • 能看懂一次 Linux 启动日志里最关键的几行。
  • 能判断启动失败大概卡在固件、bootloader、内核早期、initramfs、rootfs 还是用户态 init。
  • 能通过 efibootmgr、lsblk、blkid、findmnt、dmesg、journalctl -b 等命令核对启动链路。

0.2 非目标

本阶段暂时不深入：

  • DRAM training 具体算法。
  • UEFI SEC/PEI/DXE 内部实现。
  • Linux 解压器和 KASLR 细节。
  • setup_arch()、memblock、ACPI、PCI、IRQ 子系统源码。
  • 驱动 probe、DMA、IOMMU、SMP bring-up 的实现。

这些是后续阶段要学的内容。第一阶段只需要把启动链路“端到端跑通”，建立全局地图。

0.3 一句话模型

1. 一张总流程图

1.1 启动主链路

flowchart TD
    A[按下电源键或虚拟机启动] --> B[固件初始化平台<br/>BIOS 或 UEFI]
    B --> C{启动模式}
    C -->|UEFI| D[读取 NVRAM BootOrder]
    C -->|Legacy BIOS| E[按 BIOS Boot Order 读启动扇区]
    D --> F[定位 ESP 中的 EFI 程序<br/>例如 shimx64.efi/grubx64.efi/systemd-bootx64.efi]
    E --> G[读取 MBR/VBR<br/>跳转 bootloader]
    F --> H[bootloader 启动]
    G --> H
    H --> I[读取启动配置<br/>grub.cfg 或 loader entry]
    I --> J[加载 Linux 内核镜像<br/>vmlinuz/bzImage]
    I --> K[加载 initramfs/initrd]
    I --> L[拼接 kernel cmdline]
    J --> M[按 Linux boot protocol 交接]
    K --> M
    L --> M
    M --> N[内核解压和早期初始化]
    N --> O[解析 cmdline/内存图/ACPI/EFI 信息]
    O --> P[挂载并执行 initramfs 中的 /init]
    P --> Q{找到真正 rootfs?}
    Q -->|是| R[switch_root 到真正根文件系统]
    Q -->|否| S[进入 emergency shell 或 kernel panic]
    R --> T[执行 /sbin/init 或 systemd]

1.2 启动材料流向

flowchart LR
    Firmware["BIOS/UEFI 固件"] --> Loader["bootloader / EFI stub"]
    Firmware --> FirmwareData["固件生成或保留的信息<br/>E820 / UEFI memory map<br/>ACPI / SMBIOS / EFI tables"]
    FirmwareData --> Loader

    Loader --> KernelImage["Linux kernel 镜像<br/>vmlinuz / bzImage"]
    Loader --> InitramfsImage["initramfs / initrd 镜像"]
    Loader --> Cmdline["kernel cmdline"]
    Loader --> BootParams["boot_params / setup_data<br/>入口状态、地址、大小、指针"]

    KernelImage --> Kernel["Linux kernel 入口"]
    InitramfsImage --> Kernel
    Cmdline --> Kernel
    BootParams --> Kernel

    Kernel --> EarlyInit["内核早期初始化<br/>解析 cmdline、内存图、固件表"]
    EarlyInit --> InitramfsInit["initramfs 中的 /init"]
    InitramfsInit --> Rootfs["真正 rootfs"]
    Rootfs --> UserInit["/sbin/init 或 systemd"]

图中 FirmwareData -> Loader -> Kernel 表示固件生成的数据由 bootloader 或 EFI stub 以地址、指针、表项或启动参数的形式交给内核；多数情况下不是把 ACPI/SMBIOS 表完整复制一份给内核。

1.3 每个阶段最该看的东西

阶段关键对象主要检查点
固件BIOS/UEFI setup、BootOrder、ESP、启动热键机器是否能进入固件设置；能否看到磁盘；启动项是否存在。
bootloaderGRUB、systemd-boot、shim、EFI stub菜单是否出现；配置是否指向正确内核和 initramfs。
内核入口vmlinuz、initramfs、cmdline、boot protocol选择菜单后是否出现内核日志；cmdline 是否正确。
内核早期dmesg、early console、E820/EFI memory map是否有 Linux version、Command line、e820、efi 日志。
initramfs/init、udev、dracut/initramfs-tools、驱动是否能找到根设备；是否能解密、组装 LVM/RAID。
rootfs/init/sbin/init、systemd、fstab是否完成 switch_root；用户态服务是否启动。

2. 最小知识闭环

第一阶段不是背术语，而是建立一个能用于排障的闭环。

2.1 闭环问题 1：谁启动谁？

重点：

  • UEFI 通常不是直接启动“操作系统”，而是启动一个 EFI 程序。
  • GRUB、systemd-boot、shim、Linux EFI stub 都可以是 EFI 程序。
  • Linux kernel 被加载后，还要自己解压并进行早期初始化。
  • initramfs 是内核启动后运行的早期用户空间。
  • 真正的系统服务通常在 rootfs 中由 systemd 或其它 init 启动。

2.2 闭环问题 2：每一棒交接了什么？

交接交接内容
固件 → bootloaderCPU 可执行环境、设备访问接口、启动设备路径、EFI/BIOS 服务。
bootloader → 内核内核镜像、initramfs 地址、kernel cmdline、内存图、固件表指针。
内核 → initramfs一个已运行的内核、临时根文件系统、设备节点/udev、内核参数。
initramfs → rootfs已找到并挂载的真实根文件系统、清理后的早期环境。
rootfs → initPID 1，后续用户态服务管理。

2.3 闭环问题 3：失败时怎么判断位置？

现象大致阶段
按电源键无反应电源/主板/EC/BMC，还没到固件。
能进 BIOS，但没有启动项固件、磁盘、ESP、NVRAM。
有 GRUB 菜单，但选项错误bootloader 配置。
选择内核后黑屏，无任何内核日志内核入口、显控输出、early console、KASLR 或 boot protocol。
有 Linux version 但找不到根内核已启动，问题在 initramfs/rootfs/cmdline/驱动。
已进入 systemd 但服务失败已过内核启动主链路，问题在用户态。

4.1 UEFI 路径

  • 一个或多个 Boot#### 启动项。
  • EFI System Partition，即 ESP。
  • ESP 上的 .efi 文件。

通俗理解：

UEFI 像一个会读 FAT 分区的启动经理。它不是盲读磁盘第一个扇区，而是按启动项记录去 ESP 里找一个 .efi 程序来运行。

4.2 Legacy BIOS 路径

Legacy BIOS 启动通常依赖：

  • BIOS boot order。
  • MBR 第一个扇区。
  • MBR 末尾 0x55AA 签名。
  • VBR/PBR 或 bootloader 后续阶段。

通俗理解：

Legacy BIOS 像只会读“第一张纸”的老管理员。它读取磁盘第一个扇区，然后把后面的事情交给那 512 字节里的小程序。

4.3 初学者重点

这一段要掌握：

  • 当前系统是 UEFI 还是 Legacy 启动。
  • ESP 挂在哪里。
  • EFI 启动项指向哪个文件。
  • bootloader 文件是否存在。
  • BIOS/UEFI 是否能看到启动磁盘。

5. 第二段：bootloader 找到内核

5.1 bootloader 是什么

bootloader 是固件和内核之间的程序。常见实现：

  • GRUB：功能强，支持复杂文件系统、LVM、加密、多系统菜单。
  • systemd-boot：简单，主要面向 UEFI 和 EFI stub 内核。
  • shim：Secure Boot 环境下常见的第一阶段加载器。
  • Linux EFI stub：内核自己作为 EFI 程序被加载。

通俗理解：

固件只负责打开大门，bootloader 负责告诉你今天进哪个房间、拿哪份内核、带哪些启动参数。

6. 第三段：bootloader 把启动材料交给内核

6.1 启动材料有哪些

bootloader 至少要准备：

  • Linux 内核镜像：vmlinuz 或 bzImage。
  • initramfs：例如 initramfs-linux.img、initrd.img-*。
  • kernel cmdline：例如 root=UUID=... console=... quiet。
  • 内存图：E820 或 UEFI memory map。
  • 固件表信息：ACPI、SMBIOS、EFI system table 等。
  • framebuffer 或控制台信息。

通俗理解：

启动内核不是“把一个文件扔进内存”这么简单，还要附上地址清单、使用说明、临时工具包和机器布局图。

6.2 kernel cmdline 是排障核心

cmdline 会直接影响内核启动行为。典型参数：

参数作用
root=UUID=...指定真正根文件系统。
ro / rw根文件系统初始只读或读写。
quiet减少日志输出。排障时通常去掉。
splash启动画面。排障时通常去掉。
console=ttyS0,115200n8输出日志到串口。
earlycon启用早期控制台。
loglevel=7提高日志详细程度。
ignore_loglevel忽略日志等级限制，尽量输出。
init=/bin/sh直接运行 shell，用于用户态排障。
rd.break在 initramfs 特定阶段中断，常见于 dracut。
rootdelay=10等待根设备出现。
nokaslr关闭 KASLR，便于调试地址相关问题。

第一阶段只需知道：

  • bootloader 和内核之间有固定协议。

7.3 没有日志怎么办

如果选择内核后黑屏：

  1. 去掉 quiet splash。
  2. 增加 loglevel=7 ignore_loglevel。
  3. 有串口时增加 console=ttyS0,115200n8 earlycon。
  4. 虚拟机里把串口输出重定向到终端或文件。
  5. 尝试 nomodeset 排除显卡模式切换导致的黑屏。
  6. 尝试 nokaslr 排除早期地址随机化干扰调试。

通俗理解：

黑屏不等于没启动。可能只是日志打到了别的控制台，或者显卡切换模式后显示路径断了。

8. 第五段：initramfs 找到真正 rootfs

8.1 initramfs 是什么

initramfs 是内核启动后挂载的临时根文件系统，里面通常有：

  • /init。
  • shell 和基础工具。
  • udev 或设备发现逻辑。
  • 存储驱动或模块。
  • LVM/RAID/加密盘工具。
  • 挂载真正 rootfs 的脚本。

通俗理解：

initramfs 是内核随身带的“应急工具箱”。真正的系统盘还没挂上之前，先用工具箱里的工具找到并打开系统盘。

8.2 为什么需要 initramfs

常见原因：

  • 根文件系统在 NVMe、USB、SCSI、RAID、LVM、加密盘上，需要先加载驱动或组装。
  • 根文件系统需要通过 UUID、LABEL、网络或复杂路径查找。
  • 需要先解密 LUKS。
  • 需要先启动 udev 等设备发现。
  • 需要在挂载 rootfs 前执行自定义逻辑。

8.3 rootfs 查找链路

flowchart TD
    A[内核执行 initramfs 中的 /init] --> B[解析 /proc/cmdline]
    B --> C[加载必要内核模块]
    C --> D[启动设备发现<br/>udev 或脚本轮询]
    D --> E{root= 指向的设备出现?}
    E -->|否| F[等待 rootdelay 或进入 emergency shell]
    E -->|是| G{需要解密/LVM/RAID?}
    G -->|是| H[解密或组装块设备]
    G -->|否| I[挂载 rootfs]
    H --> I
    I --> J[switch_root 到真正根文件系统]
    J --> K[执行 /sbin/init]
