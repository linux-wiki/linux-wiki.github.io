BIOS 硬件识别与信息获取原理

1. BIOS 是什么

BIOS（Basic Input/Output System）是固化在主板 SPI FLASH 芯片上的一层固件，承载于一小片 8 脚 SOIC 封装的 NOR Flash（典型容量 16–32MB）。CPU 上电复位后执行的第一条指令就落在这片 Flash 映射到的物理地址上。其核心职责是：

  1. 探测并初始化硬件 — 主板上的所有设备，从 CPU 自身到每一个插槽
  2. 构建系统硬件信息表 — 为操作系统提供完整的硬件拓扑和资源分配
  3. 加载操作系统 — 从存储设备读取引导程序并移交控制权

2. BIOS 探测的核心理念：没有”上帝视角”

BIOS 本身也是一段程序，它没有”预先知道接了哪些硬件”的魔法。它必须通过一组标准协议和已知端口地址来主动探测。核心手段可以分为以下几类：

探测手段适用对象原理
固定地址 I/O 寄存器芯片组、PIC、PIT、RTC、KBC架构规范锁死了端口号，直接读
CPU 内置指令CPU 自身CPUID / RDMSR / RDPMC
总线协议读寄存器PCI/PCIe、SMBus、LPC按协议发送地址帧，看设备是否应答
命令/响应协议SATA、NVMe、USB发送标准命令，解析返回的数据结构
内存扫描ACPI/SMBIOS 入口在约定地址范围搜索魔法数字签名
探测写回BAR 大小探测写全 1，读回看哪些位被硬件硬编码为 0

BIOS 没有 USB 枚举的”上帝能力”去直接看到 USB 设备——它先要通过 PCI 枚举找到 xHCI 控制器，再通过 xHCI 寄存器操作端口，最后才能发现插了什么 USB 设备。每一层都是根据上一层的发现结果递进探测的。

3. BIOS 整体启动流程

CPU 上电复位 (第一条指令 @ 0xFFFFFFF0, 执行 BIOS ROM 中的代码)
  │
  ├── 阶段 0: 早期复位向量
  │     ├── BSP/AP 识别 (通过 LAPIC ID 判断谁初始化)
  │     ├── 清 EFLAGS, 关 NMI, 关 SMIs
  │     └── FAR JMP → BIOS 真正入口 (0xF000:0xE05B 附近)
  │
  ├── 阶段 1: 芯片组早期初始化
  │     ├── 探测 Host Bridge (PCI 0:0:0) → 确定芯片组型号
  │     ├── 探测 LPC Bridge (PCI 0:31:0) → 确定南桥型号
  │     ├── 配置 CPU 到 DRAM 的 System Agent (IMC)
  │     └── Cache-as-RAM (CAR) 设置 (无 DRAM 时的运行环境)
  │
  ├── 阶段 2: 内存初始化 ★
  │     ├── SMBus 探测 SPD (每个 DIMM 插槽)
  │     ├── 内存控制器时序训练 (Memory Training)
  │     └── 启用 DRAM → 至此 C 代码可运行
  │
  ├── 阶段 3: 总线枚举
  │     ├── PCI/PCIe 总线枚举 (深度优先遍历)
  │     ├── LPC 桥下 ISA/Serial/Super I/O 设备
  │     └── BAR 空间分配 & IRQ 路由
  │
  ├── 阶段 4: 外设初始化
  │     ├── USB 控制器 + 端口枚举
  │     ├── SATA/NVMe 存储控制器 + 设备信息
  │     ├── 键盘/VGA/串口 控制台
  │     └── 网络 PXE 启动 (可选)
  │
  ├── 阶段 5: 构建信息表
  │     ├── E820 内存映射
  │     ├── ACPI (DSDT/SSDT/MADT/MCFG/SRAT/DMAR...)
  │     └── SMBIOS (Type 0/1/2/4/7/17...)
  │
  ├── 阶段 6: 启动设备选择
  │     ├── 按 BBS (BIOS Boot Specification) 顺序尝试
  │     ├── 读 LBA 0 → 验证 0x55AA
  │     └── 加载到 0x7C00 并 JMP
  │
  └── 阶段 7: 移交控制权

4. 芯片组探测 — 平台身份的起点

在探测任何外部设备之前，BIOS 必须先知道”自己在什么平台上运行”。芯片组型号决定了后续所有寄存器的基址、初始化顺序和参数表。这一步走错了，整个启动过程全部报废。

4.1 物理拓扑：CPU 与 PCH 的互联

现代 Intel x86 平台的物理结构如下——CPU 是 SoC 化封装，PCH 是独立的外部芯片，二者通过 DMI/OPI 私有总线互联：

                                          │  ×4 或 ×8 PCIe Lane
                                   │  (≈ PCIe Gen3, 每条 8GT/s)
                 ▼
 ┌─────────────────────────────┐
 │          PCH (Platform                                                                      │
 │       Controller Hub)                                                                       │

 │  │  └─ RTC / HPET / 8259                                                   │ │
 │  └──────────────────────────┘ │
 └─────────────────────────────┘

DMI（Direct Media Interface）是 Intel CPU 与 PCH 之间的私有总线链路，走的是 PCIe 电气层协议但使用专用的链路管理。DMI 3.0/4.0 等效于 PCIe 3.0 ×4 或 ×8。

OPI（On-Package Interconnect）是 DMI 的升级版，物理层相同，但封装内互连延迟更低。

AMD 等效的互连是 Infinity Fabric / GMI，连接 CPU CCD（Core Complex Die）和 IOD（I/O Die，集成了对等的”南桥”功能）。

4.2 芯片组架构演变

年代架构CPU 集成南桥连接总线
~2008 前传统 NB/SB只有 Core独立的 MCH (北桥) + ICH (南桥)FSB + DMI
~2011 Sandy BridgeSA/PCHIMC + PCIe Root + IGPPCH (单芯片南桥)DMI 2.0

对 BIOS 而言，探测到的 Device ID 不仅决定寄存器基址，也决定了整个平台的能力集合（如支持的 PCIe 代次、DDR 类型、DMI 链路速度、USB 端口数等）。

4.3 前置条件：Cache-as-RAM — 没有内存时如何读 PCI 配置空间

BIOS 探测芯片组的第一个矛盾是：芯片组的寄存器在 PCI 配置空间/MMIO 空间，但 MMIO 的读写需要 DRAM 做地址路由，而 DRAM 此时还没有初始化。

解决方案是 Cache-as-RAM (CAR)：BIOS 在上电后的最初阶段，将 CPU 的 L1/L2 Cache 配置为”不分驱逐写入 RAM 的伪内存”模式（通过设置 MTRR 将一段物理地址标记为 Write-Back 并填满 Cache），用 L1/L2 缓存当临时的栈空间。CAR 模式下，IN/OUT 指令访问 I/O 端口（如 0xCF8/0xCFC）完全不需要 DRAM——这些 I/O 端口事务是直接路由到芯片组的。

BIOS 顺序:
1. CPU 上电, 执行 SPI ROM 中的复位向量
2. 设置 MTRR, 将一段物理地址范围标记为 Cache-as-RAM
3. 直到这一步, 栈建立在 CPU L1/L2 缓存上
4. IN 0xCF8 → 设置 PCI 地址, IN 0xCFC → 读 Host Bridge Vendor ID
   ▲ 这一步不需要 DRAM!!
5. 确定芯片组型号后, 才开始 Memory Training (需要 DRAM 可用)
6. 训练完成后 DRAM 可用 → 切换到正常栈

4.4 Host Bridge（BDF 0:0:0）完整寄存器映射

Host Bridge 在 Intel 架构中对应 System Agent（SA）的 PCI 代理，固定在 Bus 0, Device 0, Function 0。BIOS 通过 0xCF8/0xCFC 直接读取。

MCHBAR 内部空间示例：

MCHBAR + 偏移:
  0x4000: 内存通道 0 地址解码寄存器
  0x4400: 内存通道 1 地址解码寄存器
  0x4800: 内存时序 (tCL/tRCD/tRP/tRAS/tRFC 等)
  0x4C00: 内存训练控制/状态寄存器组
  0x5000: MAD (Memory Address Decoder) 通道间交错
  0x5800: DDR PHY 控制和状态
  0x5C00: 内存热管理寄存器

DMIBAR 内部空间示例：

DMIBAR + 偏移:
  0x00: DMI Link Capability (最大速度、宽度)
  0x04: DMI Link Control (目标速度、ASPM)
  0x08: DMI Link Status (协商速度、宽带)
  0x20: DMI VC0 资源控制
  0x24: DMI VC0 资源状态

BIOS 探测 Host Bridge 的完整事件序列：

1. 读 BDF 0:0:0, Offset 0x00 → Vendor ID
   ├─ 读到的值:
   │   0xFFFF → Host Bridge 未就绪 (极早期 PCH 还在复位), 等待后重试
   │   0x8086 → Intel 平台
   │   0x1022 → AMD 平台
   │   其他   → VIA/SiS/NVIDIA 等旧平台 (BIOS 可能不支持, 报错)

2. 读 Offset 0x02 → Device ID
   → 遍历 BIOS 内置的 device_id_table:
      struct {
          u16 device_id;
          u8  platform_family;   // 1=Desktop, 2=Mobile, 3=Server
          u8  dmi_version;        // 1/2/3/4
          u8  max_ddr_speed;      // 0=DDR4-3200, 1=DDR5-4800...
          u8  pcie_gen;           // 3/4/5
          u8  usb_ports;          // 总 USB 端口数
          u16 sata_ports;         // 总 SATA 端口数
          u32 mchbar_base;         // MCHBAR 默认基址
          u32 dmibar_base;         // DMIBAR 默认基址
          u32 epbar_base;          // EPBAR 默认基址
          ...
      } platforms[];

   → 匹配成功 → 设置全局 platform 指针, 载入全部基址信息

3. 读 Offset 0x08 → Revision ID (步进)
   → 用于查询 Intel/AMD 的 Specification Update 表
   → 决定是否需要应用特定 Stepping 的 Workaround

4. 读 Offset 0x0E → Header Type
   → bit7=0 (单功能) 或 bit7=1 (多功能 Host Bridge)
   → Header Type & 0x7F == 0 → 标准 PCI Header

5. PCI 扩展能力链表遍历:
   读 Offset 0x34 → CAP_PTR (首次能力偏移)
   while cap_ptr != 0:
       CapID = read_config(BDF, cap_ptr)
       if CapID == 0x09:   记录 PCI Bridge Subsystem Vendor ID
       if CapID == 0x10:   记录 PCI Express 根复合体能力
       if CapID == 0x14:   记录 Advanced Features (ACS)
       cap_ptr = read_config(BDF, cap_ptr+1)

关键：Host Bridge 的 Capability 还描述了有多少个 Root Port——BIOS 在后续 PCI 枚举中需要知道从 Bus 0 的哪些 Device/Function 开始扫描。Intel 平台通过 Host Bridge 的 DEVEN 寄存器（偏移 0x54）和 CAPID0 寄存器（偏移 0xE0）读取 Root Port 的数量和 BDF 分配。

4.5 DMI / OPI 链路初探

CPU 与 PCH 之间的 DMI 链路在 BIOS 探测 Host Bridge 时同步初始化。链路的电气训练由芯片组硬件自动完成（类似 PCIe Link Training），但 BIOS 需要读取训练结果来确认连接速度。

DMI 链路初始化流程:
1. Hardware Training (自动):
   - DMI TX/RX 通道自动建立 (接收器检测、速率协商、通道翻转等)
   - 完成后, DMIBAR 偏移 0x08 (Link Status) 生效

2. BIOS 读取 DMIBAR[Link Status]:
   - bit[19:16] = 协商的 PCIe 速率 (1=2.5G, 2=5G, 3=8G, 4=16G GT/s)
   - bit[9:4]   = 协商的通道宽度 (×1/×2/×4/×8)

3. 判断:
   if 协商速率 < 最大能力: 降档运行, 发出 POST Warning
   if 协商速率 >= 8 GT/s: DMI 3.0+ 模式, OK
   if 协商速率 < 5 GT/s: 非常旧平台, 可能不支持

4. 读取 DMIBAR 偏移 0x0C (RCLK Status) 验证 DMA 时钟是否正确

4.6 PCH（LPC Bridge / ISA Bridge） — 南桥的 PCI 代理

LPC Bridge 位于 BDF 0:31:0（Intel 平台），Class Code 0x060100（ISA Bridge）。它是 PCH 在 PCI Bus 0 上最重要的设备，内部包含整个 PCH 的核心控制寄存器。

但 PCH 不止 BDF 0:31:0。PCH 内部集成了数十个 PCI 设备，它们在 Bus 0 上按规范的 BDF 分布。BIOS 需要通过 Chipset Datasheet 中的固定 BDF 表来访问每一个内部设备。以下是以 Intel 600 系 PCH (Alder Lake/Raptor Lake) 为典型的完整 BDF 映射：

0xD0-0D7  中断路由寄存器
0xDC-0DF  RCBA+Power Mgmt Config    PWRMBASE

RCBA（Root Complex Base Address）空间是 PCH 另一套重要的寄存器集，通过 MMIO 方式映射，内部包含：

RCBA + 偏移:
  0x0000: RCBA 版本 ID
  0x1000: PCH 芯片组配置寄存器
  0x2000: HPET 配置
  0x3000: GPIO 配置
  0x3100: GPIO 路由
  0x3400: LPC 桥配置 (COM/LPT/KBC 解码)
  0x3418: LPC 通用解码范围 1
  0x3500: Flash Protection Range 寄存器 (BIOS Range Write Protect)
  0x3800: I/O 解码基址 (已废弃, 现在用 0x80-0x87 替代)

BIOS 探测 LPC Bridge 的完整事件序列：

1. 读 BDF 0:31:0, Offset 0x00 → Vendor ID
   ├─ 0xFFFF → PCH 不存在或未就绪 (ERROR!)
   └─ 0x8086 → 继续

2. 读 Offset 0x02 → Device ID (PCH 型号)
   → 从 PCH ID 表获取:
      - PCH 家族 (如 Z790/B760/H770/Q670)
      - USB 端口数量和类型分布
      - SATA 端口数量
      - PCIe Lane 数量
      - ME/CSME 固件版本范围

3. 读 Offset 0x40 → PMBASE
   → 验证 ACPI PM 寄存器可读写
   → 读 PMBASE + 0x0C → PM_TMR (24 位 ACPI 定时器) 验证 ACPI 计时是否工作

4. 读 Offset 0x60 → RCBA
   → 通过 MMIO 地址访问 RCBA 空间
   → 读 RCBA+0x0000 → 验证 RCBA 版本

5. 读 Offset 0x80 → LPC_GENERIC_DEC_RANGE1
   → 检查哪个范围被 BIOS 预解码给 EC/KBC
   → 若需要, 重新编程

6. 读 Offset 0xA0 → BIOS_CNTL
   → bit1 == 1 → BIOS Locked! (只能通过硬重启解锁)
   → bit5 == 1 → SMM 写保护已开启

7. 遍历 Bus 0 上 PCH 固定 BDF 表:
   for each (dev,func,pch_device_name) in pch_bdf_table:
       vid = read_config(0, dev, func, 0x00)
       if vid != 0xFFFF:
           记录该设备存在
           若 DID 与预期不同 → 记录为 Silicon 变体, 更新平台结构体
       else:
           若该设备在 Datasheet 中标为 "必须存在" → POST Error!
           若标为 "可选" → 跳过

4.7 PCH 内部关键功能模块的探测

确定了 PCH 型号后，BIOS 依次初始化 PCH 的各个内部模块。以下列出需要特别处理的关键设备：

SPI Flash Controller (BDF 0:31:5)：

这是 BIOS 访问自身存储的唯一通道。PCH 内 SPI 控制器直接连接到主板上的 SPI Flash 芯片。
BIOS 在探测阶段不需要"重新初始化" SPI 控制器（因为 CPU 是通过 PCH SPI 直接从 Flash
取指令的），但需要:

1. 读 SPI BAR0 → 确定 SPI 寄存器 MMIO 基址
2. 读 Flash Descriptor 区域 (Flash 的首个 4KB Sect):
     - 签名 0xFF0A (Intel Flash Descriptor)
     - Flash 布局 (BIOS/ME/GBE/Platform 数据区域的大小)
     - Master Access 权限 (CPU/ME 对各区域的读写权限)
3. 检查 Flash Descriptor 的 VSCC (Vendor Specific Component Capabilities)
     → 确定 Flash 的 JEDEC ID 和指令集 (Write Enable/Erase/Write 所需命令序列)
4. 设置 FREG (Flash Region) 寄存器, 保护 ME 区域防止 BIOS 误写
5. 若发现整个 Flash 被加锁 → BIOS 无法写入自己 → 只能运行不更新微码

MEI / HECI (BDF 0x16:0) — Intel Management Engine Interface：

ME 是 PCH 内一个独立的 ARC/X86 核心，运行完整的 Minix 或 ThreadX 操作系统。
BIOS 需要:
1. 读 BDF 0x16:0 的 BAR0 → MEI MMIO 基址
2. 通过 MEI 协议 (HECI / MEI Bus) 发送 "DRAM Init Done" 消息
3. ME 返回: 加密引擎状态、固件版本、PCH 的 Fuse 状态
4. 向 ME 请求 End-of-POST 消息 → ME 知道引导过程到了哪步

SMBus 控制器 (BDF 0:31:4)：

这在前文 SPD 读取时已经使用。BIOS 在此处:
1. 读 BAR0 → SMBus I/O 基址
2. 验证 Host Status 寄存器可读写
3. 设置 SMBus 时钟频率 (通常 100kHz)

GPIO Communities：

PCH GPIO 是平台最复杂的配置之一，每个引脚可独立配置为 GPIO/原生功能。
BIOS 需要:
1. 从 LPC Bridge 读 GPIOBASE → 得 GPIO 社区 0 的 I/O 基址
2. 每个社区包含:
     - GPIOCFG (配置寄存器): 功能选择 (GPIO/原生1/原生2/原生3)
     - GPIOROUTE: IOxAPIC / SCI / SMI / NMI 路由选择
     - GPIOTXSTATE: 输出值
     - GPIORXSTATE: 输入值
3. 遍历所有 GPIO 社区 (通常 4-12 个社区, 每个社区最多 32 个引脚)
4. 根据平台配置表将关键引脚设置为正确模式:
     - M.2 SATA/PCIE Select → 原生功能
     - BIOS Recovery → GPIO 输入
     - 主板 ID Strapping → GPIO 输入 (读主板版本)

4.8 AMD 平台差异

AMD 平台在 Broadcom (2017+) 的 Zen 架构后采用了与 Intel 不同的物理结构，但 BIOS 访问的方式一致——都通过 PCI 配置空间读 Host Bridge (BDF 0:0:0) 来判断平台。

AMD 平台读 BDF 0:0:0:
  Vendor 0x1022 → AMD
  Device ID:
    0x1450 → X370  (Zen 1)
    0x1480 → X470  (Zen+)
    0x14B5 → X570  (Zen 2/3 IOD)
    0x14D8 → B650  (Zen 4)

AMD 没有传统 LPC Bridge（因不使用 Intel 的 PCH 而是自家 FCH/整合 IOD），但 BIOS 仍通过 PCI 枚举发现 FCH 内部的 SMBus、SATA、USB 等设备（BDF 地址集不同）。

5. CPU 自身识别

5.1 CPUID — 不依赖 PCI 总线的自省

CPUID 指令是 CPU 内部的纯硬件指令——不需要外部总线、不需要内存。BIOS 唯一需要确认的只是”在执行 CPUID 之前我已经保证 CPU 处于稳定状态”。

CPUID 的硬件工作机制：

CPU 微码内部维护了一组 Model-Specific 的值寄存器。当指令解码器遭遇 CPUID 时：

  1. 读 EAX 作为输入 selector (leaf)
  2. 读 ECX 作为子叶子号 (sub-leaf)
  3. 硬件多路复用器根据 leaf/sub-leaf 从内部的 200+ 个只读 MSR 中选择返回数据
  4. 结果写入 EAX/EBX/ECX/EDX

关键 CPUID 叶子号汇总：

Leaf (EAX)ECX返回信息
0x00-最大基础叶子号 + 厂商字符串 “GenuineIntel”/“AuthenticAMD”
0x01-Family/Model/Stepping (EAX), Feature Flags (ECX/EDX)
0x02-缓存和 TLB 描述符
0x040-NL1/L2/L3 缓存拓扑：大小、组相联、缓存线大小、共享信息
0x06-温度传感器 / Turbo Boost / EIST
0x070扩展特性标志 (AVX2/AVX-512/SMAP/CET/SGX)
0x0A-性能监控计数器 (PMC) 版本和数量
0x0B0-N拓扑枚举: SMT(1)/Core(2)/Package(3) 层级
0x0D0-NXSAVE/XRSTOR 状态区大小 (FPU/SSE/AVX/AMX)
0x15-TSC 晶振频率 / 核心频率比例
0x16-Processor Base Frequency (基准频率 MHz)
0x80000000-最大扩展叶子号
0x80000001-Long Mode / NX / SYSCALL / 1GB Pages 能力
0x80000002-04-Processor Name String (48 ASCII)
0x80000006-L2 缓存大小和 Line Size
0x80000008-物理地址位数 / 虚拟地址位数

5.3 CPU 拓扑探测

BIOS 通过 CPUID Leaf 0x0B 递归枚举 SMT→Core→Package 的层级关系：

APIC ID 分解：

APIC_ID (32 位):
    [ pkg_id ] [ core_id ] [ smt_id ]
     ←───────────→
     其中 smt_id 的低 smt_shift 位有效

     pkg_id  = (APIC_ID & ~core_mask) >> core_shift

5.4 MSR 寄存器 — 不在 CPUID 中的信息

某些 CPU 信息只能通过 RDMSR（Read Model-Specific Register）获取：

MSR 0xCE (MSR_PLATFORM_INFO):
    bits [15:8]  = 最大非 Turbo 倍频 (Max Non-Turbo Ratio)
    bits [47:40] = 最大效率倍频 (Minimum Ratio)
    bits [50:48] = 编程倍频限制

MSR 0x1A0 (MSR_MISC_FEATURE_CONTROL):
    控制 TCC/TDC/Thermal 状态

IA32_FEATURE_CONTROL (MSR 0x3A):
    bit 0 = 锁定位 (1=写入被锁, 只能硬重启解锁)
    bit 1 = 允许 VMX 在 SMX 外
    bit 2 = 允许 VMX 在 SMX 内

MSR 0x198 (IA32_PERF_STATUS):
    [15:0] = 当前 P-State 的倍频值

MSR 0xE8 (IA32_MPERF) 和 0xE7 (IA32_APERF):
    用于计算当前 CPU 负载比例 (aperf/mperf × base_freq)

6. 内存探测：SMBus + SPD + 时序训练

内存是 BIOS 初始化中最复杂的环节，因为它需要先完成电气层面的握手，才能开始读取数据。

6.1 DDR 内存架构简介

现代 x86 平台的内存控制器（IMC, Integrated Memory Controller）已经集成在 CPU 内部，每个内存通道连接 1–2 个 DIMM 插槽，每个 DIMM 上有多个 DRAM 芯片（Rank），它们共用地址/命令总线，每个芯片贡献 4/8/16 位数据线。

CPU 封装
  ├── Core Complex (CCX)      → 计算核心
  ├── System Agent (SA)       → PCIe 根复合体 + 显示输出
  └── Integrated Memory Controller (IMC) → 2 个通道:
        ├── Channel A → DIMM0, DIMM1
        └── Channel B → DIMM0, DIMM1

6.2 SMBus 探测 SPD

SPD 芯片焊在每个 DIMM 插槽旁，通过 SMBus（I²C 物理层）与 PCH/IMC 通信。BIOS 上电后通过 PCH 内的 SMBus 主机控制器逐个读取。

SMBus 主机控制器的寄存器基址由 PCH 内部硬件锁死为 I/O 0xEFA0（或通过 PCI BDF 0:31:4 的 BAR0 确定——不同平台可能不同，BIOS 根据阶段 4 中探测到的芯片组型号决定具体的端口号）。

SMBus 主机控制器 I/O 寄存器 (I/O 基址 + 偏移):
   偏移 0x00: HST_STS  (Host Status)     — 状态位 (INTR/BUSY/FAILED/...)
   偏移 0x02: HST_CNT  (Host Control)    — 命令位 (START/BYTE_DATA/WORD_DATA/...)
   偏移 0x03: HST_CMD  (Host Command)    — EEPROM 偏移 (发送给 SPD)
   偏移 0x04: XMIT_SLVA (Transmit Slave Addr) — DIMM 地址 (0x50/0x51/0x52/0x53)
   偏移 0x05: HST_D0   (Host Data 0)     — 数据寄存器低字节
   偏移 0x06: HST_D1   (Host Data 1)     — 数据寄存器高字节

BIOS 读取 SPD 的完整流程：

1. 检查每个 DIMM 插槽 (0x50/0x51/0x52/0x53):

2. for each slave_address in {0x50, 0x51, 0x52, 0x53}:
     // 先从偏移 0x00 读 1 字节，看设备是否存在
     outb(XMIT_SLVA, (slave_address << 1) | 1)   // 7位地址 + R/W=1
     outb(HST_CMD, 0x00)                          // 读偏移 0x00
     outb(HST_CNT, 0x48)                          // START + BYTE_DATA

     等待 HST_STS.BUSY=0
     if HST_STS.FAILED == 1:
        continue;  // 该插槽没有 DIMM

     // 连续读 256 字节 (DDR3) 或 512 字节 (DDR4/DDR5)
     for offset in range(0, spd_size):
        outb(HST_CMD, offset)     // 设置要读的偏移
        outb(HST_CNT, 0x48)       // START
        等待 HST_STS.BUSY=0
        spd_data[offset] = inb(HST_D0)

3. 解析每个 DIMM 的 SPD 数据 → 得到模块容量、时序、电压等

SPD EEPROM 内部关键字节（DDR4，共计 512 字节）：

偏移    长    内容
─────────────────────────────────────────
0x00    1    写入字节数 (0x10 SPD总字节数) + SPD 版本
0x01    1    SPD 版本号
0x02    1    DRAM 类型 (DDR4=0x0C, DDR5=0x12)
0x03    1    模块类型 (UDIMM=2, RDIMM=1, LRDIMM=4)
0x04    1    SDRAM 密度 (每颗芯片容量) + 逻辑 Bank 数

0x0C    1    tRFC (粗粒度)

0x12-15  4    主时序: tAA, tRCD, tRP, tRAS/tRC
0x16-17  2    tRAS + tRC
0x18    1    tFAW (最小四窗口激活)
...

6.3 内存控制器初始化：Memory Training

SPD 只告诉了”这个内存条说明书上写的时序参数”。但每个 DIMM 插槽到 CPU 的走线长度不同，信号延迟也不同。Memory Training 就是自动校准这些电气参数的过程。

这个过程的硬件实现位于 CPU 内存控制器内部的一组寄存器——BIOS 通过向 IMC 寄存器写入特定的训练命令序列，让硬件自动执行训练算法：

▲ 这里 BIOC 不需要自己收发 DDR 信号！它是通过设置 IMC 寄存器，
  由 IMC 硬件自动完成训练回路。

BIOS 做的事:
  1. 向 IMC 写入训练模式选择寄存器
  2. 等待训练完成状态位
  3. 读回校准结果寄存器

IMC 硬件做的事 (自动):
  ┌─────────────────────────────────────────┐
  │ DQS (Data Strobe) 门控训练                                                                                                   │
  │   目的: 找到 DQS 选通脉冲的有效窗口                                                                                    │
  │   做法: 硬件用 DRAM 的 MPR                                                                                                  │
  │    (Multi-Purpose Register) 读回已知                                                                                        │
  │    数据，逐步延迟 DQS 采样点直到                                                                                         │
  │    数据正确，记录窗口中心                                                                                                     │
  ├─────────────────────────────────────────┤
  │ Write Leveling (写延迟均衡)                                                                                                     │
  │   目的: 补偿从 IMC 到 DRAM 的                                                                                               │
  │        飞行时间差异                                                                                                                  │
  │   做法: DRAM 使用 CK 的边沿采样                                                                                          │
  │        DQS，IMC 逐步延迟 DQS 边                                                                                            │
  │        沿直到 DRAM 反馈结果对齐                                                                                             │
  ├─────────────────────────────────────────┤
  │ Read/Write DQ Deskew (数据线去时滞)                                                                                  │
  │   目的: 补偿同一字节通路内 8 条 DQ                                                                                       │
  │        线之间的时间偏差                                                                                                           │
  │   做法: 每条 DQ 独立延迟，写已知模式                                                                                   │
  │        读回，找到 eye diagram 中心                                                                                          │
  ├─────────────────────────────────────────┤
  │ Vref 校准 (参考电压)                                                                                                                │
  │   目的: 选择使误码率最低的参考电压                                                                                      │
  │   做法: 扫描 Vref 范围，在每个点                                                                                            │
  │        执行 W/R 测试，选误码率最低点                                                                                     │
  ├─────────────────────────────────────────┤
  │ RTT/ZQ 校准 (终端电阻/驱动强度)                                                                                          │
  │   目的: 匹配传输线特性阻抗以减少反射                                                                                   │
  │   做法: ZQ 引脚外接 240Ω 精密电阻，                                                                                    │
  │        IMC 校准内部可编程电阻与其匹配                                                                                   │
  └─────────────────────────────────────────┘

训练完成后 DRAM 方可读写，C 代码才有可用的栈和堆。

7.4 ECAM (MMIO Enhanced Configuration Access)

PCIe 引入了增强配置访问机制（ECAM），把每个 Bus 的 256 个 Device × 8 个 Function × 4096 字节配置空间平铺成连续内存映射区域，通过 ACPI MCFG 表声明基址：

每个总线占用: 256 (Device) × 8 (Function) × 4096 (ConfigSpace) = 8 MiB
内存中直接寻址:
    addr = ECAM_BASE + (Bus << 20) + (Device << 15) + (Function << 12) + Offset

BIOS 在阶段 5（构建 ACPI）时填写 MCFG 表，告诉操作系统 ECAM 的物理基址和设备寻址方式。

7.5 枚举算法及完整事件序列

BIOS 的 PCI 枚举就是一个深度优先搜索算法：

全局变量: next_bus = 1   (Bus 0 由 Host Bridge 自身占用)

枚举函数: enumerate_bus(bus_number)
  for device = 0 to 31:
    for function = 0 to 7:

      // 步骤 1: 探测是否存在
      Vendor ID = read_config(bus, device, function, 0x00, 2)
      if Vendor ID == 0xFFFF:
          continue   // 该 BDF 没有设备

      // 步骤 2: 读取设备身份
      Device ID     = read_config(bus, device, function, 0x02, 2)
      Class Code    = read_config(bus, device, function, 0x09, 3)
      Header Type   = read_config(bus, device, function, 0x0E, 1)
      SubsysVenID   = read_config(bus, device, function, 0x2C, 2)
      SubsysID      = read_config(bus, device, function, 0x2E, 2)
      CapPtr        = read_config(bus, device, function, 0x34, 1)
      Revision      = read_config(bus, device, function, 0x08, 1)

      // 步骤 3: 探测扩展能力
      while CapPtr != 0:
          CapID  = read_config(..., CapPtr,     1)
          CapVer = read_config(..., CapPtr + 1, 1)
          switch (CapID):
              0x01: PCI Power Management
              0x05: MSI
              0x10: PCI Express ← 包含 Link Cap/Status, Dev Cap/Status
              0x11: MSI-X
          CapPtr = read_config(..., CapPtr + 1, 1)  // Next Capability

      // 步骤 4: 判断是否需要递归枚举下游
      if HeaderType & 0x01 == 0x01:  // PCI-PCI 桥
          // 分配次级总线号
          secondary_bus = next_bus
          next_bus += 1

          write_config(..., 0x18, secondary_bus, 1)  // Secondary Bus
          // Subordinate Bus 暂不写入，等下游枚举完再回填

          enumerate_bus(secondary_bus)               // 递归!

          // 回填 Subordinate Bus
          write_config(..., 0x19, next_bus - 1, 1)   // Subordinate Bus

      // 步骤 5: 非桥设备，检查单功能/多功能
      // 若 HeaderType bit7 == 0 (单功能)，停止该 Device 的 Function 循环

    顶层调用: enumerate_bus(0)

7.6 BAR 大小探测与地址分配

BAR 的高位在只读时返回硬件锁定的”需要多少地址空间”，软读改写后便能测出：

探测 BAR 大小:
    addr = BAR_offset  (0x10, 0x14, 0x18, 0x1C, 0x20, 0x24)

    原值 = read_config(bus, dev, func, addr, 4)
    write_config(bus, dev, func, addr, 0xFFFFFFFF, 4)
    读回值 = read_config(bus, dev, func, addr, 4)
    write_config(bus, dev, func, addr, 原值, 4)   // 复原

    if (读回值 == 0):
        BAR 不存在，跳过

    if (读回值 & 1 == 1):   // I/O BAR
        掩码 = 0xFFFFFFFC
        大小 = (~(读回值 & 掩码)) + 1
    else:                    // Memory BAR
        type = (读回值 >> 1) & 3  // 00=32bit, 10=64bit
        掩码 = 0xFFFFFFF0
        大小 = (~(读回值 & 掩码)) + 1
        if type == 2:  64bit BAR → 下个 BAR 也属于它

    从全局 I/O 或 MMIO 地址空间分配对应大小的对齐区域
    write_config(bus, dev, func, addr, allocated_base, 4)

8. 传统 I/O 设备 — 固定地址的”隐式探测”

有些设备不需要 PCI 枚举——它们的 I/O 端口地址由传统 PC 架构锁定，BIOS 无需”探测存在性”，只需要检测是否真的存在。

8.1 8259 PIC (可编程中断控制器)

I/O 端口地址 (固定):
  0x20: Master PIC 命令端口
  0x21: Master PIC 数据端口
  0xA0: Slave PIC 命令端口
  0xA1: Slave PIC 数据端口

BIOS 探测:
  1. 通过 ICW1-ICW4 (初始化命令字) 重新初始化 PIC
  2. 写入 ICW1 (0x11): 边沿触发 + 级联模式 + 需要 ICW4
  3. ICW2: 设置中断向量基址 (Master=0x08, Slave=0x70)
  4. ICW3: 通知 Master/Slave 的级联关系
  5. ICW4: 设置 8086 模式 + 自动 EOI
  6. 全部写完后验证 OCW1 (屏蔽寄存器) 是否可读写

8.2 8254 PIT (可编程间隔定时器)

I/O 端口地址 (固定):
  0x40: 计数器 0 数据端口
  0x41: 计数器 1 数据端口
  0x42: 计数器 2 数据端口
  0x43: 控制字寄存器

BIOS 探测:
  写入 0x43 (控制字) → 选择计数器 0 + 模式 3 (方波) + 16位计数
  写入 0x40 低字节、高字节 → 设置分频值
  读回 0x40 验证计数是否递减

8.3 RTC/CMOS (实时钟)

I/O 端口地址 (固定):
  0x70: RTC 地址寄存器 (bit7 = NMI 禁用)
  0x71: RTC 数据寄存器

  RTC 寄存器:
    0x00-0x09: 时间/日期/闹钟
    0x0A:      状态 A (UIP = Update In Progress 标志)
    0x0B:      状态 B (12/24h, 二进制/BCD 格式)
    0x0C-0x0D: 状态 C, D (中断标志, 有效 CMOS)
    0x0E-0x3F: POST 诊断码 & 用户设置

BIOS 探测: RTC 没有"不存在"的可能 (在 PCH 内部固定集成)
  直接读取 0x0D bit7 → 若为 1 表示 CMOS 电池有效
  读取 0x00-0x09 验证时间数值范围满足 BCD 格式

8.4 8042 键盘控制器 (KBC)

I/O 端口地址 (固定):
  0x60: 数据端口 (读=接收缓冲, 写=发送缓冲)
  0x64: 命令端口 (读=状态, 写=命令)

BIOS 探测:
  1. 读 0x64 状态寄存器:
     bit0 = 1 (输出缓冲满) → 可能有多余数据
     bit1 = 1 (输入缓冲满) → 当前不能写入

  2. 等 OBF=0, IBF=0 后，向 0x64 写入 AAh (自检命令)

  3. 等待 0x60 输出, 预期返回 0x55 (自检通过)

  4. 若返回 0x55: 
     → KBC 存在且正常
     → 继续发送 0xAB (键盘接口初始化) → 键盘存在
     → 发送 0xA7 (禁止鼠标) / 0xA8 (使能鼠标)
  
  5. 若读 0x60 在几次重试后仍无返回:
     → PCH 可能没有 Super I/O 的 KBC (较新平台)
     → 直接跳过, 用 USB 键盘

8.5 Super I/O 芯片与 LPC 总线

Super I/O 芯片（如 Nuvoton NCT6798D、ITE IT8689E）挂在 LPC 总线上，内部集成了：

Super I/O 内部模块:
  ├── UART (串口 1-4)            → 0x3F8 / 0x2F8 / 0x3E8 / 0x2E8
  ├── LPT (并口)                 → 0x378 / 0x278
  ├── Floppy Controller          → 0x3F0
  ├── GPIO (通用 I/O)            → 平台特有
  ├── Hardware Monitor           → 温度/风扇/电压
  ├── WDT (Watchdog Timer)       → 可编程看门狗
  └── ACPI Embedded Controller   → 笔记本的电池/热键/亮度

BIOS 探测 Super I/O:
  1. 通过 LPC Bridge (BDF 0:31:0) 的寄存器知道 Super I/O 基址

  2. 向 Super I/O 芯片写入配置序列 (通常是 0x87 0x87 → 进入 PnP 模式):
     outb(2E, 0x87); outb(2F, 0x87)  // ITE/Nuvoton 进入模式

  3. 读取 Chip ID:
     outb(2E, 0x20); chip_id = inb(2F)
     → 查到 {0xCA: "NCT6798D", 0x3890: "IT8689E", ...}

  4. 启用需要的外设 (如 UART#1):
     outb(2E, 0x07); outb(2F, 2)     // LDN=2 (串口)
     outb(2E, 0x30); outb(2F, 1)     // 使能 !
     outb(2E, 0x60); outb(2F, 0x03); outb(2E, 0x61); outb(2F, 0xF8)
     // → 串口即映射到 0x3F8

  5. 退出配置模式:
     outb(2E, 0xAA)  // ITE/Nuvoton 退出

9. 存储设备探测

9.1 SATA AHCI 控制器与设备识别

SATA/AHCI 是通过 PCI 枚举发现的第一个 Mass Storage 控制器（Class=0x01, Sub=0x06）。找到控制器后，BIOS 需要进一步向物理端口发 ATA 命令来知道到底接了什么样的硬盘。

AHCI 寄存器结构：

AHCI BAR（BAR5）内存映射到 HBA 寄存器区，其中 Port 0 起每个端口有独立的 PxCLB/PxFB/PxIS 等寄存器：

HBA Memory Registers (偏移自 ABAR):
  0x000: CAP     (Host Capabilities)   — 端口数量、64位支持
  0x004: GHC     (Global Host Control) — HBA 复位、AHCI 使能、中断使能
  0x008: IS      (Interrupt Status)
  0x00C: PI      (Ports Implemented)   — 位图 (bit0=1 → Port 0 实现)
  0x010: VS      (AHCI Version)        — 1.0/1.1/1.2/1.3
  ...
  0x100: Port 0 PxCLB (Command List Base Address)
  0x108: Port 0 PxFB  (FIS Base Address)
  0x110: Port 0 PxIS  (Interrupt Status)
  0x118: Port 0 PxIE  (Interrupt Enable)
  0x128: Port 0 PxSIG (Signature) → 检测设备类型
  0x12C: Port 0 PxSSTS (Serial ATA Status) → DET=3h 表示设备已连接
  0x130: Port 0 PxSCTL (Serial ATA Control)
  ...

BIOS 探测 SATA 设备的完整流程：

1. PCI 枚举 Class=0x01 Sub=0x06 → SATA AHCI 控制器
   Vendor/Device → Intel/AMD/ASMedia AHCI

2. HBA 初始化:
   ABAR = BAR5
   MR(ABAR + 0x004, GHC.AE=1)     // 启用 AHCI 模式
   Ports = CAP & 0x1F              // 总端口数

3. for each port in ports:
      // 检查端口是否已实现
      if (PI bit port == 0): continue

      // 检查是否有设备连接
      ssts = MR(ABAR + 0x100 + 0x80*port + 0x28)  // PxSSTS
      if (ssts & 0x0F != 3): continue  // DET=3→设备存在

      // 分配 Command List 和 FIS 的内存
      CLB = alloc_aligned_1K_phys()
      FB  = alloc_aligned_256B_phys()
      MR(ABAR + 0x100 + 0x80*port + 0x00) = CLB
      MR(ABAR + 0x100 + 0x80*port + 0x08) = FB

      // 启用端口 DMA (PxCMD.ST=1)
      MR(ABAR + 0x100 + 0x80*port + 0x18, ST=1)

      // 等待设备就绪
      while (MR(PxTFD) & 0x88): spin

      // 发送 IDENTIFY DEVICE (ATA Command 0xEC)
      设置 Command Header [0]:
         CFL=5  (5 个 FIS 的单位)
         P=1    (Prefetchable)
         W=0    (Read)
         PRDT length = 512
      设置 Command Table:
        FIS = H2D Register FIS with Command=0xEC (Identify Device)
        PRDT[0] = DBA (物理地址) + DBC (512字节)
      启动命令: MR(PxCI) = 1

      // 等中断完成后解析 512 字节 IDENTIFY 数据:
      struct ata_identify:
        Word 0    : 设备类型 (bit15=0→ATA, bit15=1→ATAPI)
        Word 1-9  : 默认柱面/磁头/扇区 (CHS)
        Word 10-19: 序列号 (20字节ASCII)
        Word 23-26: 固件版本
        Word 27-46: 型号
        Word 60-61: LBA48 总扇区数 (QWORD) ← 容量
        Word 76   : NCQ 支持及队列深度
        Word 83   : 支持的命令 (LBA48/TCQ/...)
        Word 106  : 物理扇区大小 / 逻辑扇区大小
        Word 117-118: SSD/PIO 参数

9.2 NVMe 控制器与设备识别

NVMe 走 PCIe 通道，Class=0x01 Sub=0x08，用一种完全不同于 SATA 的命令队列机制与 SSD 通信。

NVMe 寄存器空间（由 BAR0 映射）：

偏移 0x00: CAP  (Controller Capabilities)
           [15:0]  = MQES (最大队列条目数)
           [37:32] = CSS (I/O 命令集, bit0=1→NVM Express)

偏移 0x08: VS   (版本)

偏移 0x14: CC   (Controller Configuration)
           [0] = EN (使能控制器)

偏移 0x1C: CSTS (Controller Status)
           [0] = RDY (控制器就绪)

偏移 0x24: AQA  (Admin Queue Attributes)
           [11:0]  = ASQS (Admin SQ 大小)
           [27:16] = ACQS (Admin CQ 大小)

偏移 0x28: ASQ  (Admin SQ 基址, 64位物理地址, 4K 对齐)
偏移 0x30: ACQ  (Admin CQ 基址, 64位物理地址, 4K 对齐)

BIOS 探测 NVMe 设备的完整流程：

1. PCI 枚举 Class=0x01 Sub=0x08 ProgIF=0x02 → NVMe 控制器
   BAR0 = MMIO 寄存器基址

2. 控制器初始化:
   MR(CC.EN) = 0                    // 关掉控制器 (若已开启)
   while (MR(CSTS.RDY) != 0): spin  // 等待就绪位清除

   MR(AQA) = (31<<16 | 31)          // ASQ=31, ACQ=31 (32 个条目)
   ASQ_phys = alloc_4K_aligned(N * sizeof(64B SQ Entry))
   ACQ_phys = alloc_4K_aligned(N * sizeof(16B CQ Entry))
   MR(ASQ) = ASQ_phys
   MR(ACQ) = ACQ_phys

   MR(CC) = I/O SQES=6 (64字节), I/O CQES=4 (16字节), EN=1
   while (MR(CSTS.RDY) != 1): spin  // 等待就绪

3. 发送 Identify Controller 命令:
   构造 SQ Entry [0]:
     OPC (Opcode) = 0x06  (Admin Identify)
     CID (Command ID) = 0
     NSID = 0  (Identify Controller)
     PRP[0] = output_buffer_phys (4096 字节对齐)
   提交: 写 SQ Tail Doorbell

   等待 CQ Entry → 解析结果:
     struct nvme_identify_ctrl:
       PCI VID       : [63:48], [1:2]
       PCI SSVID     : [67:64]
       Serial Number : [4:23]   (20 字节 ASCII)
       Model Number  : [24:63]  (40 字节 ASCII)
       Firmware Rev  : [64:71]  (8 字节 ASCII)
       NN            : [516:519]  → 支持的 Namespace 数量

4. 对每个 Namespace:
   发送 Identify Namespace (OPC=0x06, NSID=NsID, CNS=0)
   解析结果:
     NSZE    = QWORD [0]      → 总逻辑块数
     NCAP    = QWORD [8]      → 总容量 (字节)
     LBAF[i] : 
       [130 + i*4 + 0] = MS (元数据大小)
       [130 + i*4 + 3] = LBADS (LBA 数据大小, 如 2^9=512B, 2^12=4096B)
     FLBAS : [26] & 0x0F → 当前格式化的 LBAF 索引

10. USB 控制器发现与设备枚举

USB 是 PCI 枚举的下游设备。BIOS 先找到 USB 主机控制器，再通过控制器访问下游设备。

10.1 四种 USB 控制器类型

ClassSub名称速度关键寄存器特点
0x0C030x00UHCI (Intel)USB 1.1 (12Mbps)I/O 端口, 固定帧列表
0x0C030x10OHCIUSB 1.1 (12Mbps)MMIO, HCCA 共享内存
0x0C030x20EHCIUSB 2.0 (480Mbps)MMIO, 周期/异步调度
0x0C030x30xHCIUSB 3.x (5–20Gbps)MMIO, 完整设备上下文模型

BIOS 识别流程：

PCI 枚举 → 发现 USB 控制器
  → 检查 Class Code:
      0x0C0300 → UHCI  (读 I/O BAR)
      0x0C0320 → EHCI  (检查伴随的 UHCI companion)
      0x0C0330 → xHCI  (读 MMIO BAR, 支持全部 USB 版本)

BIOS 在 UEFI/CSM 模式:
  若同时有 EHCI 和 xHCI → xHCI 优先, USB3 可借用 xHCI 的 USB2 端口
  若只有 EHCI + UHCI → 每个 UHCI 端口有自己的 companion EHCI 映射

10.2 xHCI 端口探测与地址分配

xHCI 提供了一个非常干净的设备模型，每个物理端口有一个 PORTSC 寄存器，所有操作通过 Doorbell + 命令环来完成。

xHCI 寄存器基址来自 PCI BAR0，操作流程：

1. 控制器初始化:
    停止 HC (USBCMD.RS=0), 等待 USBSTS.HCH=1
    分配 DCBAAP (Device Context Base Address Array Pointer)
    分配 Command Ring
    分配 Event Ring (ERST)
    写 USBCMD.RS=1 启动控制器
    等待 USBSTS.HCH=0

2. 探测每个端口:
    EXT_CAPS = 遍历 xHCI 扩展能力寄存器链:
      找到各协议 (USB3 Gen1/Gen2, USB2) 关联的端口范围

    for (port = 1; port <= MAXPORTS; port++):
        PORTSC = 读端口状态控制寄存器 (偏移 = 0x400 + port*0x10):
          CCS (Current Connect Status) bit0  = 1? → 设备已连接
          PED (Port Enabled/Disabled) bit1  = 1? → 端口已启用
          PP  (Port Power) bit9  = 1? → 供电已开

        若 CCS=1 且 PED=0:
          → 写 PORTSC.PP=1 (给端口加电)
          → 写 PORTSC.PR=1 (触发端口复位)
          → 等待 PED=1 (复位完成, 设备可以通信)

3. 分配设备上下文和地址:
    分配 Device Context Base Address (64字节 × 32 Slots)
    发送 Enable Slot 命令 (Command Ring):
        → Command Completion 返回 Slot ID (1-255)

    写 Input Context (Slot = slot_id):
        Slot Context:
           Root Hub Port Number = port
           Speed = PORTSC.PS (1=Full, 2=Low, 3=High, 4=Super, 5=SuperPlus)
        EP0 Context:
           Max Packet Size = 8 (默认) + 其他属性

    发送 Address Device 命令:
        Input → Device Context Base Array + Input Context
        → 硬件执行后, 返回 Output Context (实际分配的 USB 设备地址)

4. 读取设备描述符:
    Doorbell EP0 传输:
        Setup Packet: 80 06 00 01 00 00 08 00
                      (bmReqType=IN, bReq=GET_DESCRIPTOR,
                       wVal=DEVICE, wLen=8)
    设备返回 8 字节设备描述符:
        bLength         (1)    = 18 (USB 2.0+) 或 12 (USB 1.x)
        bDescriptorType (1)    = 1 (Device)
        bcdUSB          (2)    = USB 版本 (如 0x0320=3.2)
        bDeviceClass    (1)
        bDeviceSubClass (1)
        bDeviceProtocol (1)
        bMaxPacketSize  (1)    = 8/16/32/64/512

5. 再次发送 Address Device 命令，更新 EP0 MaxPacketSize 为真实值

11. 平台固件表 — BIOS 给操作系统的”接口”

BIOS 把所有探测到的硬件信息打包进三张表：

11.1 E820 — 物理内存布局

BIOS 在所有探测完成后，汇总各区间的物理内存情况，通过 INT 15h AX=E820h 提供。操作系统（或 bootloader）逐块读取，构成可用的物理内存池。

11.2 SMBIOS — 硬件资产清单

BIOS 在物理内存的 0xF0000–0xFFFFF 区域内写入 SMBIOS 入口点（_SM_ 或 _SM3_ 签名），表中包含每个硬件组件的字符串化描述（Type 0/1/2/4/7/17/19…）。Linux 需扫描此区间找到 _SM3_ 后解析。

11.3 ACPI — 设备树与电源管理

BIOS 构建 RSDP（Root System Description Pointer），其物理地址在内存中可扫描 RSD PTR 字符串找到，指向 RSDT/XSDT 表，再指向 MADT、MCFG、DSDT/SSDT、SRAT、DMAR 等数十个子表。DSDT 包含整个设备的 AML 字节码（ACPI Machine Language），操作系统内部的 ACPICA 解释引擎执行这些字节码，将设备树注册到设备模型中。

上图展示的是一条严格的分层递进链路，自上而下分为四个层级：

第一层 · 复位入口 — CPU 上电后从 0xFFFFFFF0 取第一条指令，执行 SPI ROM 中 BIOS 的复位向量代码。此时没有内存、没有设备信息，唯一可用的是 CPU 内部的 L1/L2 缓存（Cache-as-RAM）作为临时栈。

第二层 · 芯片组识别 — BIOS 做的第一件事是通过固定 BDF 0:0:0（Host Bridge）和 0:31:0（LPC Bridge）读 PCI 配置空间，获取 Vendor/Device ID。这一步确定平台型号后，后续所有设备的寄存器基址、初始化参数表才有据可查。若此步失败，BIOS 无法继续。

第三层 · 五路并行探测 — 芯片组就绪后，五条探测线路同时展开：

  • CPUID 走 CPU 内部指令通道，不依赖外部总线，直接读出型号、缓存拓扑、特性标志和核心数
  • SMBus 通过 I²C 协议访问每个 DIMM 插槽上的 SPD EEPROM，获取内存条容量和时序参数，随即触发 IMC 硬件执行 Memory Training 使 DRAM 可用
  • PCI/PCIe 通过 0xCF8/0xCFC 或 ECAM 遍历全部 BDF 空间，深度优先枚举所有桥和终端设备，读出 Vendor ID / Device ID / Class Code，并为每个设备分配 BAR 地址空间和 MSI/MSI-X 中断向量
  • 固定 I/O 按 PC/AT 遗留端口号直接访问 PIC、PIT、RTC，写命令字后读回验证设备存在
  • LPC 总线 通过 0x2E/0x2F 端口进入 Super I/O 芯片的 PnP 配置模式，依次使能所需的传统外设

第四层 · 数据汇总 — 五路探测完成后，探测到的全部信息汇入三张标准表交给操作系统：E820 表描述物理内存布局（哪些地址可用、哪些被硬件占用）；ACPI 表（MADT/MCFG/DSDT/SRAT/DMAR 等）描述设备树、中断路由、NUMA 拓扑和 IOMMU 映射；SMBIOS 表（Type 0/1/2/4/7/17 等）提供人类可读的硬件资产清单。操作系统通过这些表获取全部硬件信息，开始构建自己的设备模型和驱动框架。
